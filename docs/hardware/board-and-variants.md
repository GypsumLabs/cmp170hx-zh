# 板卡及其变体

**本页内容。** 本页介绍 CMP 170HX 的实体 PCB：它源自哪种设计、NVIDIA 有意删去了哪些元件、两种在售变体及所有可靠的区分方法，还会说明板卡和料号代码、连接器布局、VRM、跳线电阻阵列、各 SKU 的熔丝裁剪情况，以及板上的裸焊盘能说明什么、不能说明什么。

**先澄清两个事实。**

1. **CMP 170HX PCB 是 NVIDIA A100 40 GB PCIe 参考设计，只是有意删去了部分元件。** 板上每个元件的设计编号，都能与泄露的 NVIDIA Tesla A100 电气原理图 `NVIDIA-A100-GA100-883-P1001-B02-Rev-A.pdf`（PG100/PG101 系列）对应。对应的**明确是** 40 GB PCIe 板，而不是 80 GB 版，也不是 SXM 版。
2. **在售变体恰好有两种，而且它们解锁后的容量不同。** **8 GB** 卡（`10de:20c2`）可解锁到 **64 GB**；**10 GB** 卡（`10de:2082`）可解锁到 **40 GB**。两者绝不能混淆。有人曾在 10 GB 卡上尝试 80 GB 配置，但结果不稳定；参见[80 GB 问题](../frontier/80gb.md)。

## 两种变体一览

| 属性 | 8 GB 变体 | 10 GB 变体 |
|---|---|---|
| PCI ID | `10de:20c2`（`0x20C2`） | `10de:2082`（`0x2082`） |
| 子系统 | `0x158510DE` | `0x155710DE` |
| 板卡料号 | `900-11001-0108-000` | `900-11001-0105-000` |
| GPU 料号 | `20C2-105-A1` | `2082-105-A1` |
| 板卡 ID | 未记录 | `0x8100` |
| 量产 VBIOS | `92.00.67.00.01`（2021-05-14） | `92.00.66.00.02`（2021-04-23） |
| HBM 厂商 | SK Hynix **HBM2e** | Samsung **HBM2** |
| 活动 FBPA / FBP | 24 中的 16 / 12 中的 8 | 24 中的 20 / 12 中的 10 |
| 活动堆叠 / 总线宽度 | 4 堆，4096-bit | 5 堆，5120-bit |
| 出厂容量 | 8192 MiB | 10240 MiB |
| **解锁到** | **65536 MiB（64 GB）** | **40960 MiB（40 GB）** |
| 解锁 CFG1 `0x009a0204` | `0x02779000` | `0x02669000` |
| 解锁 LMR `0x00100ce0` | `0x0000020B` | `0x0000028A` |
| `FUSE_SKU_ID` `0x00821060` | `0x80` | `0x68` |
| `OPT_GPC_DISABLE` `0x00820350` | 观察到 `0x13`、`0x25`、`0x45` | 观察到 `0x15`、`0x85`、`0xa8`：**按晶片而非按 SKU；全部留下 5 个 GPC / 70 SM** |
| `NV_PTOP_FS4` `0x0002241c` | `0x00000000` | `0x00000081` |

两者在常见信息中报告得完全一样，这正是上表重要的原因：`lspci` 对两者都显示为 `GA100 [CMP 170HX] (rev a1)`，而 `nvidia-smi` 只把产品名报告为 "NVIDIA Graphics Device"。这两个字符串都无法区分 SKU。

安装器也会检测到第三个设备 ID `10de:20b0`，但它**不会**被解锁：驱动内部的门控逻辑只接受 `0x20C2` 和 `0x2082`，因此 `20b0` 卡虽然能安装工具，却不会解锁任何功能。`10de:20b0` 是 A100 SXM4 40 GB 的 ID。

> [!CAUTION]
> **弄错变体是后果最严重的识别错误**
>
> 发布版驱动会在运行时根据 PCI 设备 ID 选择显存几何布局，因此驱动本身不会弄错。但如果有人想当然地认为“8 GB 就是 40 GB”或“10 GB 就是 64 GB”，就会误读每一次寄存器捕获、每一份容量报告和每一条排障讨论。每次都应先读取设备 ID。

## 区分它们

### 通过软件

```bash
# 1. 设备 ID 和子系统。这是权威依据。
lspci -nn -d 10de: | grep -i GA100
# 0d:00.0 3D controller [0302]: NVIDIA Corporation GA100 [CMP 170HX] [10de:20c2] (rev a1)

lspci -d 10de:20c2 -vnn | grep -i "Subsystem"
# Subsystem: NVIDIA Corporation Device [10de:1585]

# 2. 使用 nvidia-smi 交叉核对。
nvidia-smi --query-gpu=pci.device_id,pci.sub_device_id,vbios_version,memory.total \
           --format=csv

# 3. 从 InfoROM 获取板卡和 GPU 料号，以及序列号/板卡 ID。
nvidia-smi -q | grep -Ei "board part number|gpu part number|inforom|serial"
```

映射：

| `pci.device_id` | `pci.sub_device_id` | 变体 |
|---|---|---|
| `0x20C210DE` | `0x158510DE` | 8 GB，解锁到 64 GB |
| `0x208210DE` | `0x155710DE` | 10 GB，解锁到 40 GB |

### 通过寄存器（如果 PCI ID 存疑）

这些是通过 BAR0 执行的只读探测。完整映射见[熔丝与 OTP](fuses-and-otp.md)，工具说明见[验证](../procedures/verify.md)。

| 寄存器 | 8 GB | 10 GB |
|---|---|---|
| `FUSE_FBP_DISABLE` `0x00820364` | `0x00000852` | `0x00000009`（也有 `0x840`；按晶片而异） |
| `FUSE_FBPA_DISABLE` `0x00820368` | `0x00c0330c` | `0x000000c3`（也有 `0xc03000`） |
| `FBHUB_NUM_ACTIVE_LTCS` `0x00100800` | `0x10`（16） | `0x14`（20） |
| `FBPA_NUM_ACTIVE` `0x009a0164` | `8` | `0xa` |
| `FUSE_SKU_ID` `0x00821060` | `0x80` | `0x68` |
| `NV_PTOP_FS4` `0x0002241c` | `0x00000000` | `0x00000081` |
| VBIOS IFR 指纹 | `2ff19960f9175320` | `3ca3d24230d6800f` |
| VBIOS FIRMWARE 指纹 | `e2c91c1808ae2759` | `8c4e1344c51b0940` |

`NV_PTOP_FS4` 的位 0 是 `GEN2_PCIE`，位 7 是 `GEN2_PCIE_SPEED`，因此 8 GB 卡读到的 `0x00000000` 表明这两个相关位都为 0，这正是其中值得注意的部分。10 GB 卡读到的 `0x00000081`，则与 A100 80 GB、RTX 3070、GA10x 部件以及 Drive `0x20bb` 的返回值一致。

### 通过板卡和封装

| 信号 | 8 GB | 10 GB |
|---|---|---|
| 金手指上方的 PCB 丝印 | `180-11001-DAAA-B15`（也见过 `180-11001-DAAA-B35`、`180-11001-DAAA-045`） | 同一板卡家族 |
| ASIC 标记 | `GA100-105F-A1` | `GA100-105A-A1` |
| HBM 厂商（GPU-Z，或堆叠标记） | SK Hynix HBM2e | Samsung HBM2 |
| 板卡料号贴纸 / InfoROM `BRD` | `900-11001-0108-000` | `900-11001-0105-000` |

板卡料号中的 `-0108-` 与 `-0105-` 字段，是不读取 HBM 堆叠标记时最可靠的纯物理区分依据。

## 板卡代码与血统

| 代码 | 它是什么 | 与 170HX 的关系 |
|---|---|---|
| `PG100` / `PG101` | NVIDIA A100 PCIe 板卡家族，也是 170HX 上各设计编号所对应的原理图家族 | 170HX **就是**这块板的缺件版本 |
| `P1001-B02` | 具体的泄露原理图修订（`NVIDIA-A100-GA100-883-P1001-B02-Rev-A.pdf`）；第 3 页是 "IO: PCIe CONNECTOR" | 位宽改装所用电容设计编号和值的来源 |
| `180-11001-DAAA-*` | 170HX 上的 PCB 丝印料号 | `11001` 字段与板卡料号 `900-11001-*` 共享 |
| `900-11001-0108-000` / `900-11001-0105-000` | 装配板卡料号 | 8 GB / 10 GB |
| `GA100-883AA-A1` | 零售 Tesla A100 40 GB 上的 ASIC 标记 | 满规格分档，曾与 170HX 并排拍照以作对比 |
| `GA100-105F-A1` | 170HX 上的 ASIC 标记 | 精简分档。`105` 与两个 SKU 的 GPU 料号后缀 `-105-A1` 匹配 |
| `PG199` | NVIDIA DRIVE A100（A100D）**SXM2** 模块，PCI `10DE:20BB` | **不是 170HX 板。** 一个完全不同的部件 |

> [!WARNING]
> **PG199 是一个反复出现的混淆来源，有三种不同方式**
>
> 1. **PG199 不是 170HX 板代码。** 它是 DRIVE A100 SXM2 模块。它之所以反复被提出作为解锁候选，是因为它采用与 170HX 相同的显存拓扑（4 堆 Hynix HBM2e、4096-bit，按 32 GB 出售，部分来源还列出 40 GB SKU），而且不需要 PCIe 焊接。一位一手拥有者报告称，它只有 96 个 SM 而不是 108 个，可用核心时钟仅为 1140-1260 MHz，支持 PCIe 3.0 x16，散热非常困难，水冷下也难以运行训练负载。TechPowerUp 将它列为 6144-bit 的说法被认为是错误的。不存在 PG199 解锁。已有一次尝试记录：2026-07-26，研究者将修改版 cmpunlocker 应用到一块 PG199 板上，预期的 CFG1 和 LMR 写入确实生效，PLM 也已打开，但启动因 `Booter failed 0x54` 失败，GSP 始终未完成初始化。
> 2. **名为 `PG199` 的解锁器分支并未实现 PG199 支持。** 与 master 的差异只涉及 `README.md`、`common/constants.yaml`（仅注释）、`driver/build.sh`、`install.sh`、`remove.sh` 和 `requirements.txt`，此外还删除了 PR 模板。它的配置档与 master 的 8 GB、10 GB 配置逐字节相同，没有改动任何驱动补丁，仓库中也完全没有出现 `0x20BB`。它根本没有改变设备检测：master 自带的 `install.sh` 本来就会在 `10de:20c2` 和 `10de:2082` 旁边 grep `10de:20b0`，该分支只是改写 README 中的依赖说明来声称这一点。
> 3. **TechPowerUp 条目 283106 是一个 DRIVE-PG199-PROD 映像，绝不能刷到 170HX 上。** 参见[VBIOS](vbios.md)。

## 物理尺寸与安装

| 测量 | 值 |
|---|---|
| PCB 长度 | 27 cm |
| 全长度 | 29 cm，含 I/O 挡板和一个插上的 EPS 连接器 |
| 晶片周围散热器螺栓孔距 | 57 × 68 mm 中心到中心（68 mm 垂直，57 mm 水平） |
| 晶片封装 | 约 55 × 55 mm，BGA-2743 |
| 晶片面积 | 826 mm²，TSMC 7 nm，542 亿晶体管，65.6 M/mm² |
| 紧固件 | Torx T10 和 T15 |
| 导热垫 | 主区域 1.5 mm 软垫，电感 3 mm 软垫，晶片上还有液态导热膏 |

170HX 的封装图例也读 `NVIDIA / B KR 2120A1 / TBSG42.M0W e1`。

> [!NOTE]
> **未解问题**
>
> 主区域导热垫究竟是 1.5 mm 还是 2 mm。1.5 mm 和 3 mm 的数值来自一位拆开显卡并拍照的拥有者；另一位参与者给出了 "2 mm"，但前面加了 "I think"（我觉得）。两人都证实了 T10/T15 螺丝刀头。用卡尺测量一块出厂导热垫即可确定答案。

散热、拆解顺序和水冷头安装见[散热](../operations/cooling.md)。这里唯一值得重复的板级危险，源于这是一块*缺件 PCB*，而不是某种特定散热器的特性：

> [!CAUTION]
> **在放下水冷头之前，盖住每一个未贴装的 IC 焊盘**
>
> 水冷头接触柱覆盖范围内的所有未贴装 IC 焊盘，都必须用导热垫盖住；否则水冷头的金属柱可能跨接裸露的铜焊盘，导致显卡永久损坏。**170HX 是一块缺件的 A100 板，裸焊盘远多于真正的 A100，因此安装水冷头时相应更危险。** 导热垫应覆盖以下位置：ASIC 左右两侧的 DrMOS 位置、ASIC 左下和右下的位置、晶片右侧一颗电感与一颗电容之间的 PMIC，以及晶片左侧 3.3 µH 电感下方的两颗 PMIC。对于这一操作和其作用机制，置信度很高；但因果关系只建立在一块显卡上：它在安装水冷头约一小时后损坏，同时还存在一个原本就有的挖矿磨损故障，最终无法把两者明确区分开。

## 连接器布局

| 连接器 | 详情 |
|---|---|
| PCIe 边缘 | 机械上是完整 x16，**电气上也布出了 x16**；出厂时由于 12 条通道的交流耦合电容缺失，只能以 x4 训练 |
| NVLink 边缘金手指 | PCB 上**确实存在**，拆解照片中可见，A100 水冷头也会将其露出。配套 NVLink IC 是否贴装**尚未确定，但更可能是缺件**：一次直接的 A100 与 CMP 对比称元件缺失，但有另一种基于原理图的解读；参见[NVLink 硬件](nvlink-hardware.md) |
| 供电 | **1 × EPS 8-pin**，不是 PCIe 8-pin，位于右上角，带一根穿过背板的硬线缆 |
| 显示输出 | 无。没有任何显示硬件。显示输出被记录为永久缺失 |
| 未贴装 4-pin 焊盘 | 测得携带 12 V，怀疑是风扇接口 |

### EPS 连接器

供电输入只有一个 EPS 8-pin。大多数 PSU 内置 EPS 线缆的卡扣过大，物理上无法插入该接口，因此通常使用 2× PCIe-8-pin-to-EPS 转接线。相关的线缆安全规则如下：模组 EPS12V 线缆的**两端**都必须是 4× 12 V 和 4× GND，而且一颗质量合格的引脚只能承载约 70 到 80 W。设备能力结构中的插槽功耗上限为 75 W，连接器额定功率为 300 W。软件功耗上限由 VBIOS 而不是连接器决定：出厂固件最高为 250 W，只有刷有 NVIDIA 300 W OC 映像的卡才是 300 W。参见[供电与 PSU](../operations/power-and-psu.md)。

拆解时，必须先用塑料撬棒把供电线缆从背板上撬下来，板卡才能移动。PCB 也不能直接垂直抬起，因为 PCIe 连接器是滑入背板槽中的。据记录，某个知名硬件频道第一次尝试时就被这一步弄得不知所措。

> [!NOTE]
> **未解问题**
>
> 4-pin 风扇接口焊盘是否带电，并且可以用 PWM 控制？其中一颗引脚实测为 12 V。配套插座的料号未知，也没有人确认其余引脚是否带有转速计或 PWM 信号。在空闲和负载状态下探测另外两颗引脚，再结合泄露原理图追踪信号，就能回答这个问题。它之所以重要，是因为这可能让每张卡在不使用外部控制器的情况下独立控制风扇。

## 删除了什么，以及它意味着什么

这是本页的核心。四类缺失带来的后果完全不同。其中，NVLink 接口 IC 是否缺失只是报告中的结论，并未得到确认：关于是否贴装，双方都有直接证据，问题仍未解决。

| 缺失元件 | 后果 | 能否恢复？ |
|---|---|---|
| PCIe 交流耦合电容，通道 4-15（24 × 0402） | 链路以 x4 而不是 x16 训练 | **可以。** 手工焊接后已可靠复现 |
| VRM 相位：DrMOS 晶体管及其输出电感 | 尚未测出任何影响 | 物理上可以，但功能上没有意义 |
| NVLink 接口 IC（是否贴装**尚未确定**，见下文） | 无论是否贴装都没有 NVLink；熔丝已将其关闭 | 没有已知路径 |
| 安全模块区域（Microchip CEC1712） | 170HX 有焊盘，但没有芯片 | 不需要；缺少它反而意味着验证硬件更少 |

### PCIe 交流耦合电容：旗舰改装

这张卡只能以 x4 训练，是因为上方十二条通道（通道 4-15）的交流耦合电容**虽然已经布线到 PCB 上，却在出厂时缺失**。每个差分对需要 2 颗电容，12 条通道合计缺少 24 颗 0402 元件。手工补齐 24 颗即可恢复完整的 x16 链路，只补 12 颗则能达到 x8。这是纯物理改装，完全不需要软件补丁。

| 规格 | 值 |
|---|---|
| 封装 | 0402 |
| 值 | 220 nF（0.22 µF） |
| 介质 | **X7R**（常被误写成 "XR7"） |
| 额定电压 | ≥ 6.3 V。已知能工作的 x16 改装用了 6.3 V 部件 |
| 厂商料号 | Taiyo Yuden `MAASJ105SB7224KFCA01`（220 nF，6.3 V，X7R，0402）。Samsung `CL05B224KO5NNNC`（16 V）也报告能用 |
| 设计编号 | 大致 C1100-C1350，来自原理图第 3 页 "IO: PCIe CONNECTOR" |
| 分销商编号 | Digi-Key `3886834` 和 Digi-Key `1276-1176-1-ND` 都被引用；两者没有互相对照验证。引用厂商料号 |
| 报告的替代品 | 100 nF 16 V X7R 对一位测试者有效；另一位从一块死主板拆下等效件 |

> [!CAUTION]
> **电容改装只改变通道位宽，绝不会改变 PCIe 代数。**
>
> 一张没有使用解锁器、但完成了电容改装的卡，报告的是 **PCIe 1.0 下的 x16**。反过来，完全未改装的 **x4** 卡也曾通过软件达到 Gen2（5 GT/s）。这两个维度彼此独立。源码已经证实了这一点：发布版仓库和 12 个未发布分支的任何文件中，都没有字符串 "capacitor"、"AC coupling"、"solder" 或任何位宽寄存器；对完整 Git 历史执行 grep 也没有找到结果。实验性 `Gen2` 分支只改变链路**速度**。参见[PCIe 子系统](pcie-subsystem.md)和[PCIe Gen2](../unlock/pcie-gen2.md)。

焊接不完整或发生桥接时，链路通常会协商到下一个合法位宽（16、8、4、1），而不是完全失败，因此报告出的通道数可以直接反映焊接质量。一位改装者在三张卡上的结果随着技术提高，依次从 x4 到 x8，再到 x16。电容改装后只有 x8，意味着焊接不完整或发生了桥接，而不是存在另一种硬件限制。

返工技术、操作流程、难度和实测带宽结果见[物理改装](../operations/physical-mods.md)。简而言之：使用含铅 60/40 焊锡和凝胶助焊剂，先吸掉出厂时的无铅焊锡；约 380 °C 的尖头烙铁就足够，无需预热。该区域并不拥挤，一位改装者手工完成一张卡约需 20 分钟。有人提议先把整块板放进烤箱预热，但这个方案很快被否决；新手最常见的失败方式是用 IR 炉配合热风枪过度加热，导致 PCB 弯曲、内部走线断裂、IC 过热，事后产生极难诊断的故障。

### VRM 相位

这张卡使用 **MP86957 智能功率级，每颗额定输出 70 A**。其中若干 DrMOS 位置及其输出电感没有贴装。频道内的结论是，出厂 VRM 可处理约 500 W，缺失的相位属于冗余而非必需。实测满载功耗约为 250 W，也就是出厂功耗上限。

> [!NOTE]
> **补齐缺失的 VRM 相位没有帮助**
>
> 这一说法已从三个方面得到反驳。（a）8 GB 卡使用*完全相同*的供电，在 64 GB 下完全稳定；10 GB 卡在 80 GB 下却不稳定。（b）出现崩溃的 80 GB 卡在故障负载期间从未超过约 80 W，而出厂上限是 250 W。（c）从电气角度看，GPU 不会感知 VRM 相位数量；只安装一半 MOSFET 的 VRM 也能在满载下正常工作，只是剩余部分会更热。此外，PWM 控制器还必须重新配置，才能驱动新增相位，因此仅靠焊接元件甚至无法提高有效相位数。500 W 是根据数据手册推算的数值，从未通过实际 500 W 运行验证。

恢复完整 A100 TDP，预计只需进行简单的分流改装，而不是修改固件，但尚未有人实际完成或测量过这种改装。有人提出过将功耗上限提高到 400-500 W 的软件或 VBIOS 路径作为替代方案，但同样从未实现。

> [!NOTE]
> **未解问题**
>
> 170HX 是否需要 PCB 背面核心附近的中等尺寸 SMD 电容，即左右电容排上每颗 MOSFET 附近大约两颗？这个问题源于一张照片：拍摄者此前见过一张 RTX 2070 上有两颗此类电容脱落，导致电压异常。成对放置说明它们存在冗余，但每对至少要有一颗正常工作。这涉及本地去耦，而不是 VRM 相位，因此与上面的相位数量结论存在张力，并未被其反驳。170HX 上从未检查过这些电容。下一步是拍摄一张正常工作的 8 GB 卡和一张正常工作的 10 GB 卡的背面，再与原理图中的 C 设计编号清单对照。

### NVLink

边缘金手指确实存在。配套 IC 是否贴装**尚未确定，但更可能是缺件**：一次拆解和唯一一次直接的 A100 与 CMP 板卡对比都报告元件缺失；相对的证据包括一种基于原理图的解读，以及项目 VBIOS 对比表中声称 PCB 已完整贴装的一行。参见[NVLink 硬件](nvlink-hardware.md)。除此之外，NVLink 已在硅片中通过熔丝关闭（`FUSE_NVLINK_DIS`）；`0x00823800`-`0x0082382C` 特性覆盖块中没有 NVLink 寄存器，任何分支中也没有 NVLink 代码。`PTOP_SCAL_NUM_NVLINK` `0x0002246c` 仍然读为 `0xc`，因为这颗晶片本身是完整的 GA100。这张卡不支持 P2P。

相比之下，CMP 90HX 的导流罩有一个 NVLink 连接器的开口但 PCB 完全没有连接器，所以 170HX 在这里相对大方：走线存在。

> [!NOTE]
> **未解问题**
>
> NVLink 能否重新启用？频道内的预期是 "will require PCB mods most likely, add missing components"（很可能需要进行 PCB 改装并补齐缺失元件）。问题还受到一个假设的影响：GA100 中介层本身可能带有 eFuse，这意味着 NVLink 的断开可能是物理层面的，任何激光或焊接都无法触及。没有人对中介层进行过成像或探测。这是这张卡上最难处理的硬件问题：在未知情况之外，很可能还需要 BGA 级返工。参见[NVLink](../frontier/nvlink.md)和[NVLink 硬件](nvlink-hardware.md)。

### 缺失的安全模块

一些 A100 板上有、但 170HX 上缺失的贴装区域，被识别为 **Microchip CEC1712 安全芯片**。它最初被描述为“用于验证 VBIOS 的神秘 FPGA”，同一天又根据 NVIDIA "Data Center CEC Defeaturing"（数据中心 CEC 去功能化）最终客户通知中的引用更正了这一说法。170HX PCB 有焊盘，但没有芯片。并非所有 A100 都带有该芯片：某个 Ampere 修订版因元件短缺而在出货时省略了它，而且无法从产品列表判断。AMD MI50 也有一种类似的守卫芯片，只接受官方 VBIOS 映像。置信度为中等：从未有人从板上读出元件标记，也没有拿到数据手册。

### 流传硬件恢复 PDF 中的 Winbond 芯片

流传的 `a100-unlock.pdf` / `cmp-170hx_a100_hardware-restore.pdf` 物料清单中出现的 Winbond BIOS 芯片，是用于从刷写失败中恢复的**备份 VBIOS 芯片**。它并不是 PCIe 或显存解锁的一部分。该 PDF 的作者说过，PCIe 通道上的小元件才是实现 x16 所需的部分，而其余元件都是为了在内部尽量复刻一台 A100。一位阅读过同一指南的资深改装者认为，这份清单暗示需要使用钢网完成整套 BGA 作业，这也是该指南让人误以为一种实际上只需新手到爱好者水平的改装非常复杂的原因。置信度为中等：这一结论来自对作者解释的二手回忆，但与作者本人所说的 "only the lane parts are needed"（只需要通道部件）一致。

## 跳线电阻

板卡在靠近去耦电容的左上区域有五对跳线电阻：五个跳线共十个焊盘，元件没有标记，通常是 100 kΩ 0402，并上拉到 0 V 或 1.8 V。每个跳线由一颗电阻和一个空焊盘组成，因此把元件从一个位置移到另一个位置，就会翻转对应的跳线位。在 PCB 上从左到右依次为：

| 跳线 | 设计编号 | 功能 |
|---|---|---|
| Strap1 | R986, R987 | `RAMCFG[1]` |
| Strap0 | R989, R990 | `RAMCFG[0]` |
| Strap3 | R993, R994 | `VGA_DEVICE` |
| Strap4 | R999, R1000 | `PCIE_CFG` |
| Strap2 | R1004, R1005 | `RAMCFG[2]` |

R1004 和 R1005 是*同一个*跳线位置的两个备用焊盘，不是两颗独立电阻。同一来源还提到第六个跳线 `DEVID_SEL`（R240/R241），但它从未在实体板上被定位。

出厂跳线模式为：A100 40 GB 与 170HX 10 GB 都是 `LLLLH`；170HX 8 GB 是 `HHLLH`。两个变体的跳线电阻 2（`RAMCFG[2]`，最右侧）都是 H。A100 原理图中的 GPU STRAP CONFIGURATION 表，将 STRAP2/STRAP1/STRAP0 映射到 `RAMCFG[4:0]`：`H, L, L` = `00100` = Samsung HBM2 8 Gb 8Hi；`H, H, H` = `00111` = Hynix HBM2E 16 Gb 8Hi；`L, M, H` = `01010` = Micron HBM2E 16 Gb 8Hi，其中 M 表示中电平三态。置信度为中等：这些结论来自 VBIOS 跳线表和 A100 原理图，并非在 CMP 上实测得到。

> [!CAUTION]
> **移动显存跳线电阻不能解锁 VRAM，而且有一种模式会让卡变砖**
>
> 这一点已经从四个独立方向得到确认。（a）一位测试者在一块使用出厂 VBIOS 的 10 GB 卡上穷举后三个跳线的全部 8 种组合，报告显存容量没有变化；`LLHHH` 模式导致系统无法 POST，移除三颗跳线也没有改变任何结果。（b）第二位测试者独立报告，翻转跳线后 "did not change a thing"（一点没变）。（c）一块被重新跳线为 8 GB 出厂模式 `HHLLH` 的 10 GB 卡，仍然读到 `FBPA_CFG1_BROADCAST @ 0x009a0204 = 0x02449000`，也就是未修改的 10 GB 数值。（d）一块未改动跳线的 10 GB 卡达到了与重新跳线的卡相同的 80 GB 状态，因此任何电阻改动从来都不是前提。维护者在这一点被证明的当天就接受了这一结论。

它之所以不能工作，原因就在源码中：发布版解锁会在**驱动运行时根据 PCI 设备 ID**选择显存几何布局，而不是读取任何跳线。补丁先计算 `devId = pGpu->idInfo.PCIDeviceID >> 16`；如果 `devId == 0x20C2`，就写入 `cfg1Value = 0x02779000` 和 `lmrValue = 0x0000020B`，否则写入 `0x02669000` 和 `0x0000028A`，具体通过 `GPU_REG_WR32(pGpu, 0x009a0204U, cfg1Value)` 和 `GPU_REG_WR32(pGpu, 0x00100ce0U, lmrValue)` 完成。因此，把 `RAMCFG` 重新跳线为 8 GB 模式，不可能让 64 GB 路径应用到 10 GB 卡上。只有改变设备 ID 才能做到这一点，而设备 ID 并不由 `RAMCFG` 跳线决定。

阅读旧捕获时还应注意一个有记录的异常：一块 10 GB 卡上的不匹配跳线改动产生了 `CFG1 = 0x4266a000`，而预期值是 `0x02669000`；当时只有前四个 FBPA 和一个显存堆叠处于活动状态。

> [!NOTE]
> **未解问题**
>
> Strap3（`VGA_DEVICE`，R993/R994）和 Strap4（`PCIE_CFG`，R999/R1000）到底有什么作用？跳线图第二次发布后，这个问题于 2026-07-26 提出，但一直无人回答。`VGA_DEVICE` 跳线可能与显示输出启用有关，`PCIE_CFG` 跳线可能与链路配置有关，两者都还是未解问题。有一个意外的数据点：一位测试者原本想移动 R1004，实际却移动了 Strap4，将模式从 `LLLLH` 改成 `LLLHH`，并报告显存没有变化。PCIe 能力协商是否发生改变，从未进行测量。下一步应有意重复该实验，并在前后分别捕获 `lspci -vv` 的 LnkCap 和 LnkSta。

> [!NOTE]
> **未解问题**
>
> 在实体板上定位 R240/R241（`DEVID_SEL`）。这很重要，因为发布版驱动正是根据设备 ID 选择显存几何布局，而且 `OPT_DEVID_SW_OVERRIDE_DIS` `0x00820584` = 1 已关闭所有软件路径。已经尝试但被否定的方法包括：目视搜索 R986-R1005 所在区域、搜索 PCB 正面照片，以及询问商业 AI 助手；后者编造了一个自信的答案，被质疑后又完全推翻。一位研究者根据设计编号的排列规律认为，R240/R241 不可能靠近 R986-R1005，可能位于 PCB 另一面；他还指出，A100 和 170HX 正面的设计编号低于 500，而 Tesla V100 背面的设计编号高于 500。另一位研究者则坚持他们拍到的 M 标记电阻就是目标元件。问题至今没有定论。最好的下一步，是系统扫描设计编号低于 500 的那一面，并对照泄露原理图中的 `DEVID_SEL` 网络，而不是只根据设计编号是否相邻来判断。

## 显存封装

| | 8 GB 变体 | 10 GB 变体 |
|---|---|---|
| 厂商和类型 | SK Hynix HBM2e | Samsung HBM2 |
| GA100 封装选项 | 96 GB 更快 Hynix HBM2e（如 A100 80 GB 上） | 48 GB Samsung HBM2（如 A100 40 GB 上） |
| 活动堆叠 | 4 | 5 |
| 总线宽度 | 4096-bit | 5120-bit |
| 解锁目标 | 4 × 16 GB = 64 GB，**稳定** | 5 × 8 GB = 40 GB，**稳定**；80 GB 不稳定 |

**这种厂商差异，是“为什么 8 GB 解锁到 64 GB 后稳定，而 10 GB 解锁到 80 GB 后不稳定”的首要解释。** 8 GB 卡使用的是密度更高、速度更快的 Hynix 封装。置信度很高：至少三位参与者在一个多月内独立提出这一判断，从未被反驳，有 GPU-Z 截图支持，也与实际观察到的稳定性差异一致。

完整晶片在 24 个 FBPA 上应为 6144-bit。170HX 从未能使用这一配置。

> [!NOTE]
> **未解问题**
>
> 8 GB 卡究竟是五堆 16 GB，还是六堆、其中 12 个 FBP 有四个被禁用？流传的解锁指南写道："HBM2e: 5 stacks × 16 GB = 64 GB physically (Hynix), software-locked to 8 GB"（HBM2e：物理上 5 堆 × 16 GB = 64 GB（Hynix），软件锁定到 8 GB）。概念验证团队则称，每个 GA100 封装都有六个实体堆叠；8 GB 变体拥有 96 GB 的 Hynix HBM2e，其中 12 个 FBP 中有两个因缺陷被熔断，另有四个被标记为禁用；这些禁用的分布使两个堆叠运行完整的 1024-bit 接口，另四个只能运行 512-bit 接口。双方都同意可寻址目标是 64 GB，也都同意显存是 Hynix HBM2e。**目前更倾向于六堆的说法：**实测的 8 GB 熔丝掩码在 12 个 FBP 中留下 8 个，在 24 个 FBPA 中留下 16 个；而 5 × 16 = 64 的算术结果恰好对应解锁目标，看起来更像事后倒推出来的。但“两堆 1024-bit、四堆 512-bit”的划分，无法明显解释实测到的连续每-FBPA 死索引（2、3、8、9、12、13、22、23），后者更像是丢失了四个*完整*堆叠。去盖、进行 X 光检查，或测量每个堆叠的带宽，才能最终确定。

HBM 堆叠是邦定在**硅中介层**上的，而不是 PCB 上。因此，失效的堆叠无法通过回流焊重新投入使用。一位成员曾在几颗 HBM2 GPU 上使用热风枪、以不同温度尝试数小时，没有成功。HBM 堆叠内部也含有熔丝，因此堆叠内有缺陷的晶片可以被永久熔断。尤其是 Samsung HBM2，据报告不太耐受电压调整，而且一直没有人识别出该电压轨的控制器或测量其电压。

## 熔丝裁剪：每种变体被熔断了什么

容量上限和 SM 上限都已经烧录进熔丝，无法通过软件重新启用。完整细节见[熔丝与 OTP](fuses-and-otp.md)；与板卡有关的汇总如下：

| 寄存器 | 8 GB（`0x20C2`） | 10 GB（`0x2082`） |
|---|---|---|
| `FUSE_FBP_DISABLE` `0x00820364` | `0x00000852`（12 个 FBP 中 8 个活动） | `0x00000009` 或 `0x840`（12 个中 10 个活动） |
| `FUSE_FBPA_DISABLE` `0x00820368` | `0x00c0330c`（24 个中 16 个活动） | `0x000000c3` 或 `0xc03000`（24 个中 20 个） |
| `FUSE_FBIO_DISABLE` `0x0082036c` | `0x00c0330c` | `0xc03000` |
| `ROP_L2_DISABLE` `0x008202C4` | | `0xc03000` |
| `FBHUB_NUM_ACTIVE_LTCS` `0x00100800` | `0x10`（16） | `0x14`（20） |
| `FBPA_NUM_ACTIVE` `0x009a0164` | `8` | `0xa` |
| 已禁用的每-FBPA 索引 | 2、3、8、9、12、13、22、23 | 0、1、6、7 |

已被熔丝裁剪禁用的分区回读为 `0xbadf20xx`（例如 fbpa02 `0xbadf2011`、fbpa08 `0xbadf2014`、fbpa12 `0xbadf2016`、fbpa22 `0xbadf201b`），活动分区则回读 `0x00001000`。

对比跨卡转储时，两点要紧：

- **不存在真正的硅片缺陷，只有一个活动禁用掩码。** 对应的 DEFECTIVE 寄存器全部读为零：`FBP 0x8205CC`、`FBPA 0x8205D0`、`FBIO 0x8205D4`、`ROP/L2 0x8205E8`。向 DISABLE 寄存器写入 0 也不会改变它们。
- **具体掩码按晶片而异，但总数不变。** 10 GB 卡上观察到的 FBP 掩码包括 `0x840`（FBP6、FBP11）和 `0x00000009`（FBP0、FBP3）：索引不同，但都保留 12 个中的 10 个。观察到的 GPC 掩码包括 `0x13`、`0x15`、`0x25`、`0x45`、`0x85` 和 `0xa8`，都保留 5 个 GPC，并且都枚举出 70 个 SM。不同卡之间出现不同掩码是预期现象，并不意味着 SKU 或解锁潜力不同。

两个变体的算力部分都处于熔丝下限：5 个活动 GPC、35 个活动 TPC，以及计算能力 8.0 下的 70 个 SM，也就是 4480 个 CUDA 核心。每个 GPC 对应的 `CTRL_OPT` 寄存器（`0x00820838 + i*4`）和每个 `RECONF_OVR`（`0x00820A40 + i*4`）都读为 `0x00000000`，`OPT_GPC_DEFECTIVE 0x008205C4` = 0；根据 `OPT|RECONFIG` 计算出的熔丝下限，也恰好等于枚举数量。相比完整 GA100（8 GPC × 8 TPC = 64 TPC = 128 SM），该部件出货时只启用了晶片 54.7% 的 SM，缺失的 SM 没有任何一个可以恢复。

按每一个规模寄存器，晶片本身就是一颗完整的 GA100：

| 寄存器 | 值 | GA10x 对照卡 |
|---|---|---|
| `PTOP_SCAL_NUM_GPCS` `0x00022430` | `8` | `6` |
| `PTOP_SCAL_NUM_TPC_GPC` `0x00022434` | `8` | `4` |
| `PTOP_SCAL_NUM_FBPS` `0x00022438` | `0xc`（12） | `4` |
| `PTOP_SCAL_NUM_FBPAS` `0x0002243c` | `0x18`（24） | `4` |
| `PTOP_SCAL_NUM_LTCS` `0x00022454` | `0x18`（24） | `8` |
| `PTOP_SCAL_FBPA_PER_FBP` `0x00022458` | `2` | `1` |
| `PTOP_SCAL_NUM_NVLINK` `0x0002246c` | `0xc`（12） | `0` |
| `PTOP_FS_STATUS` `0x00022470` | `0x3f` | |
| `PMC_BOOT_0` `0x00000000` | `0x170000a1`（`0x170` = GA100，rev a1） | `0xb74000a1` |

> [!NOTE]
> **记录在案的寄存器地址更正**
>
> `0x00820C14` 是 `STATUS_OPT_FBIO`，**不是** `STATUS_OPT_FBPA`。FBPA 的熔丝裁剪状态位于 `0x00820C18`。Pascal 时代的 FBPA 熔丝地址 `0x00021C14` 在 GA100 上返回 BADF。净室工作使用的 `probe.sh` 中保留了这两个条目，并在旁边以内联注释标出更正，因此工具本身也保留了这段历史。

## 设备 ID 熔丝

两个 170HX PCI ID 都已熔入同一颗晶片。

| 熔丝 | 地址 | 10 GB 读数 | 8 GB 读数 |
|---|---|---|---|
| `OPT_PCIE_DEVIDA` | `0x008204d8` | `0x00002082` | `0x000020c2`（有争议，见下） |
| `OPT_PCIE_DEVIDB` | `0x0082056c` | `0x000020c2` | `0x000020c2` |
| `OPT_DEVID_SW_OVERRIDE_DIS` | `0x00820584` | `0x00000001` | `0x00000001` |
| `OPT_INTERNAL_SKU` | `0x008203f4` | `0x00000000` | `0x00000000` |
| `OPT_SKU_ID` | `0x00821060` | `0x00000068` | `0x00000080` |
| `OPT_SLT_REV` | `0x008204bc` | `0x00000001` | |
| `FUSE_FB_FALCON_PRI_DIS` | `0x00820670` | `0x00000000` | |
| `FUSE_OPT_SECURE_GSP` | `0x0082074c` | `0x00000001` | |
| `FUSECTRL` | `0x00820000` | `0xe0040000` | |

`FUSE_FB_FALCON_PRI_DIS` = 0 表示 Falcon 仍能访问 FB PRI 寄存器，这是显存解锁的前提。`FUSE_OPT_SECURE_GSP` = 1 表示 GSP 调试已被禁用。

**主 PCIe 设备 ID 已熔入晶片，VBIOS 和跳线电阻都无法修改；只有子系统 ID 可以由 VBIOS 设置。** DEVIDA 与 DEVIDB 之间的选择由跳线锁存（`DEVID_SEL`）；截至 2026-07-27，还没有找到只靠软件改变它的方法。某个 VBIOS 声明了备用设备 ID，只表示该 VBIOS 被*允许运行在*拥有该 ID 的卡上，并不能替显卡改牌。

> [!NOTE]
> **未解问题**
>
> 8 GB 卡上的设备 ID 熔丝值。2026-07-19，一次针对 `0x20c2` 卡的 BAR0 探测报告称，DEVIDA **和** DEVIDB 都是 `0x000020c2`。2026-07-22 的 PCIe 固件分析则称 DEVIDA 为 `0x2082`、DEVIDB 为 `0x20C2`；2026-07-24/25 对 10 GB 卡的转储也与后一种说法一致。两种说法都没有被撤回，也没有说明第二组数值对应的 SKU。可能是 8 GB 卡确实将两个熔丝都设置为 `0x20c2`，另一个来源也独立提出了这一点；也可能是某份转储的标签有误。需要注意的是，第一种读数打破了 `DEVIDB = DEVIDA | 0x40` 这一工作假设；该假设在 170HX（`0x2082`/`0x20c2`）和一张 GA10x 对照卡（`0x2484`/`0x24c4`）上都成立。只要从一张确认无误的 8 GB 卡同时转储两个熔丝，并在同一段粘贴内容中附上 `lspci -nn`，就能解决这个问题。

> [!NOTE]
> **`20B2` 不是 CMP 170HX 的设备 ID**
>
> 它曾出现在一条早期消息中，随后于 2026-06-29 在频道内被更正为 `2082`，原来只是笔误。它也出现在一份推测性的重新熔丝方案中，但在那里指的是作为*目标*的 A100 ID，语境不同。两个 170HX ID 是 `0x20C2`（8 GB）和 `0x2082`（10 GB）。

## 修订差异

这块卡上没有单一的 "revision" 轴，而是有四个彼此独立的变化方面。

| 轴 | 见过的值 | 要紧吗？ |
|---|---|---|
| 硅片修订 | 每张卡 `rev a1`（`PMC_BOOT_0` = `0x170000a1`） | 未观察到变化 |
| PCB 丝印尾字段 | `180-11001-DAAA-B15`、`180-11001-DAAA-B35`、`180-11001-DAAA-045` | 同一板卡家族；未确立功能差异。B15 和 B35 都做了 x16 电容改装且结果相同 |
| VBIOS 修订 | `92.00.67.00.01`（8 GB 量产）、`92.00.6D.00.09`（2021-11-01，300 W，无显存超频）、`92.00.6D.00.0A`（2022-04-07，300 W，432 MHz 显存字段）、`92.00.66.00.02`（10 GB 量产） | **对解锁无关。** 对功耗上限和显存时钟要紧 |
| 按晶片熔丝裁剪掩码 | 同一 SKU 的不同晶片之间 FBP 和 GPC 禁用掩码不同 | 否：总数恒定 |

**VBIOS 版本不会影响解锁是否生效。** 两台主机上的四张卡中，有两张使用 `92.00.67.00.01`，另外两张使用 `92.00.6D.00.0A`；它们的解锁和 Gen2 结果完全相同，板卡料号 `900-11001-0108-000`、GPU 料号 `20C2-105-A1` 和子系统 `0x158510DE` 也完全一致。笼统地说“8 GB 卡使用 `92.00.6D.00.0A`”是错误的：这两个版本在实际流通的显卡中都存在。完整版本信息见[VBIOS](vbios.md)。

这里还有一个供应商方面的疑点，之所以记录下来，是因为它可能表现为明显的硬件差异：一个有商业利益关系的来源声称自己掌握“two kinds of VBIOS for 170hx, one has higher bandwidth”（170hx 有两种 VBIOS，其中一种带宽更高），但没有给出版本字符串或具体数值。这至少与 364 MHz 和 432 MHz 显存字段映像都在流传的事实一致。现有记录无法判断真伪。

> [!NOTE]
> **未解问题**
>
> 提高功耗的 "unlock BIOS" 卡在长期挖矿后是否会烧毁板背面的一颗电容？一位拥有者转述称，供卡卖家曾反复遇到这种情况，并展示过一块烧毁的板；可疑元件后来缩小为一块 8 GB 板背面的两颗疑似电容。该卖家让显卡在约 56 °C 下运行，这引发了两种猜测：可能监控了错误的传感器，也可能在挖掘带宽受限的币种时使 VRM 过热。一位经验丰富的老用户表示自己从未见过这种故障，因此对此表示怀疑。没有提供故障元件的照片，也没有进行测量。拍摄一张设计编号清晰可见的故障板照片，再获取带宽受限负载下 VRM 的热电偶读数，就能解决这个问题。

## PCB 能告诉你什么、不能告诉你什么

**它能告诉你**哪些功能被移除了；借助匹配的 A100 原理图，还能准确判断哪些元件可以恢复这些功能。位宽改装就是这样推导出来的：设计编号范围、封装、数值和介质都来自原理图第 3 页，而不是猜测。

**它不能告诉你**容量或算力限制的任何信息。这些限制分布在三层中，而只有一层位于 PCB 上：

| 层 | 在哪 | 可移动？ |
|---|---|---|
| PCB 级物理缺失 | 板上 | 可以通过焊接恢复，但只涉及 PCIe 通道位宽 |
| VBIOS 固件 | SPI ROM，在 MAC 范围内 | 否，没有 csecret(2) |
| OTP 熔丝 | 晶片 | 否 |

实际发布的解锁方案不会移动其中任何一层。它由驱动在运行时覆盖寄存器状态，完全不修改硬件。在全部六个发布版补丁中，`0x0082xxxx` 熔丝空间内唯一被写入的寄存器是 `0x00823804`（FEAT PLM）、`0x0082381C`（SS0 = `0x88888888`）和 `0x00823820`（SS1 = `0x00000008`）。任何熔丝裁剪寄存器（`0x00820350`、`0x00820364`、`0x00820368`、`0x0082036C`、`0x008202C4`、`0x00820C1C`）都没有在任何地方被写入。**解锁方案重新编程的是显存几何布局；它不能、也不会让已被熔丝关闭的单元重新工作。**

### 板级失败路线

没有新信息时，不要重复尝试这些路线。完整清单见[失败路线](../history/dead-ends.md)。

| 尝试 | 为什么这是失败路线 |
|---|---|
| 通过显存跳线电阻解锁 VRAM | 穷举全部 8 种组合没有产生容量变化；`LLHHH` 会让系统变砖；移除三颗跳线也没有改变任何结果 |
| 把 `RAMCFG` 重新跳线为 8 GB 模式，让 64 GB 路径应用到 10 GB 卡 | 驱动根据 PCI 设备 ID 而不是任何跳线选择显存几何布局 |
| 补回缺失的 VRM FET、电容、线圈和电感，以稳定 80 GB | 已从三个方面被反驳（见上文 VRM 一节） |
| 通过水冷头稳定 80 GB，因为零售 A100 80 GB 没有 IHS 而 170HX 有 | 从未测试，后来被显存刷新解释取代；而且测量显示故障卡只消耗约 80 W，说明它们并非受温度限制 |
| 对 HBM 电压轨进行硬件改装，作为稳定性修复 | 没有人执行过，没有识别出控制器，也没有测量电压轨。Samsung HBM2 据报告无法很好地承受这种调整，有缺陷的 HBM 还可能在堆叠内部被永久熔断 |
| 用热风枪回流失效的 HBM2 堆叠 | 堆叠邦定在中介层上，而不是 PCB 上；有人在几颗 HBM2 GPU 上尝试数小时，没有成功 |
| 用一个 `strap5` 电阻在两个熔断的设备 ID 之间切换 | 该跳线从未被定位；一周后发布的五跳线图明确列出了五个跳线，根本没有 strap5 |
| 清除 `CTRL_OPT` 以恢复额外 SM | 全部 8 个每 GPC 的 `CTRL_OPT` 寄存器已经读为 `0x00000000`，枚举出的 35 个 TPC 也已经等于熔丝下限。GPC 禁用状态位于 `0x00820350` 的 OTP 中，而不在 `CTRL_OPT` 中 |
| 在 CMP 级显卡上进行 BGA 植球 | 已有一手尝试，但失败了：尽管 MODS 之后报告没有错误，访问 `nvidia-smi` 时仍会卡死。这个失败*模式*值得记住：即使 MODS 检查干净，显卡仍可能让驱动卡死 |
| 电容返工前把整块板放进烤箱预热 | 已作为新手陷阱否决；过度加热会使 PCB 弯曲、内部走线断裂并烧坏 IC |
| 给某些卡上发现的 "manufacturing_mode" 引脚施加 3.3 V | 确实在真实硬件上观察到过，但从未完成特征分析，也没有追踪到结果 |

> [!WARNING]
> **编造出来的板卡拓扑，读起来和真实拓扑完全一样**
>
> 这段内容作为警示性数据点逐字记录。一个商业 AI 助手被问到 R240/R241 和板卡晶体的位置时，自信地把 R240/R241 放在 "adjacent to the other high-value 100k strap resistors (such as R985-R1016)"（靠近其他高值 100k 跳线电阻，例如 R985-R1016），称它们是连接到 `FS_OVERT` 和 `PCIE_CFG` 的 100 kΩ 0402 元件，并在 PG100/PG101 原理图的 "Page 5: CLOCK GENERATION / CRYSTALS" 中列出 Y200（27.000 MHz）和 Y201（100.000 MHz 低抖动差分晶体）。当被质疑参考设计编号的逻辑时，它又完全推翻了自己的说法。这些内容没有一项可以验证。凡是没有直接从照片或原理图本身读出的设计编号、页码或网络名，都应视为未经验证。
