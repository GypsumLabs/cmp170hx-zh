# CMP 170HX 中的 GA100 晶片

**本页内容。** 物理硅片：制造工艺、晶体管数量、晶片尺寸和封装；GPC / TPC / SM 层级，以及 170HX 实际拥有多少个 SM、与 A100 相比又是多少；决定这一数量、且会随晶片而变化的熔丝裁剪配置；显存分区和缓存层级；计算能力及其对应的指令集；以及各种固定功能引擎是存在、已被熔丝裁剪禁用，还是物理上根本不存在。

结论先行：**CMP 170HX 搭载的就是与 NVIDIA A100 相同的 GA100 晶片**，采用 TSMC 7 nm 工艺，拥有 542 亿个晶体管，面积为 826 mm²。这是该晶片经过收获分级后的产品：8 GB 卡标记为 `GA100-105F-A1`，10 GB 卡标记为 `GA100-105A-A1`，并且**8 个 GPC 中有 5 个处于活动状态：35 个 TPC、70 个 SM、4480 条 FP32 通道，计算能力为 8.0**。两个 SKU 都准确枚举出 70 个 SM。CMP 的限制不会移除任何 SM，[算力解锁](../unlock/compute-throttle.md)也不会把 SM 加回来：挖矿专属的限制是由独立熔丝保存的发射速率分频器，而这块卡实际拥有的 SM 数量，就是该分级晶片通常的熔丝下限。

每张 170HX 都会在 `PMC_BOOT_0`（`0x00000000`）读到 `0x170000a1`，这是 GA100 的芯片 ID 签名。同一偏移处，GA10x 消费级对照部件读到的是 `0xb74000a1`，因此只需检查这一个 dword，就足以判断“这真的是 GA100 吗”。

## 晶片与封装

|---|---|---|
| 架构 | Ampere GA100 | 与 A100 使用同一晶片，不是 CMP 专属流片 |
| 工艺 | TSMC 7 nm（N7） | |
| 晶体管 | 542 亿 | 密度为 65.6 M/mm² |
| 晶片面积 | 826 mm² | 达到或接近 7 nm 掩模版极限（约 830 mm²） |

| `PMC_BOOT_0` `0x00000000` | `0x170000a1` | 每个有效 GA100 都是该值 |
| PCI 设备 ID | `10de:20c2`（8 GB）/ `10de:2082`（10 GB） | 参见[板卡与变体](board-and-variants.md) |
| 计算能力 | 8.0（`sm_80`） | OpenCL 3.0，CUDA 11+ |
| SM 基础 / 加速时钟 | 1140 MHz / 1410 MHz | 在 `nvidia-smi -pl 300` 下观察到 1470 MHz |

## GPC / TPC / SM 层级

GA100 的规模寄存器描述的是完整晶片，与实际被熔丝裁剪的内容相互独立。在 170HX 和 A100 类参考部件上，这些寄存器读数相同：

| 规模寄存器 | 地址 | 值 | 含义 |
|---|---|---|---|
| `PTOP_SCAL_NUM_GPCS` | `0x00022430` | `0x8` | 完整晶片有 8 个 GPC |
| `PTOP_SCAL_NUM_TPC_GPC` | `0x00022434` | `0x8` | 每个 GPC 有 8 个 TPC → 共 64 个 TPC → 完整晶片有 128 个 SM |
| `PTOP_SCAL_NUM_FBPS` | `0x00022438` | `0xc` | 12 个 FBP |
| `PTOP_SCAL_NUM_FBPAS` | `0x0002243c` | `0x18` | 24 个 FBPA（GA102 RTX 3090 读到 6） |
| `PTOP_SCAL_NUM_LTCS` | `0x00022454` | `24` | 24 个 L2 缓存切片 |
| `PTOP_SCAL_FBPA_PER_FBP` | `0x00022458` | `2` | 每个 FBP 有 2 个 FBPA |
| `PTOP_SCAL_NUM_NVLINK` | `0x0002246c` | `12` | 晶片上有 12 个 NVLink 单元 |
| `PTOP_FS_STATUS` | `0x00022470` | `0x0000003f` | 熔丝裁剪状态 |

因此，完整 GA100 应有 128 个 SM 和 8192 条 FP32 通道。但从未有产品以这一配置发布：所有 A100 SKU 发布时都是 108 个 SM / 6912 个着色单元，而 CMP 170HX 则是 70 个。

| 部件 | 活动 GPC | TPC | SM | FP32 通道 |
|---|---|---|---|---|
| 完整 GA100 晶片 | 8 | 64 | 128 | 8192 |
| A100 SXM4 / PCIe（所有 SKU） | 7（`FUSE_GPC_DISABLE` = `0x08` / `0x08` / `0x80`，探测到的三个 SKU 各有一位置 1） | 54 | 108 | 6912 |
| DRIVE A100（`0x20bb`，PG199） | 6（`FUSE_GPC_DISABLE` = `0x84`） | 48 | 96 | 6144 |
| **CMP 170HX，两个 SKU** | **5**（`RING_ENUM_GPC` = 5） | **35** | **70** | **4480** |

170HX 的这个数字来自实测，而不是推断。解锁卡上的 PTX 特殊寄存器转储工具报告 `SMs=70 warpsize=32`、`nsmid=70 nwarpid=64`，`smid` 值从 0 到 69 连续无缺口。一台由 8 张卡组成的混合矿机在全部 8 个设备上都枚举出 `cu: 70`，而显存容量在 9990 MiB 和 7954 MiB 之间交替，这清楚地证明了 SM 数量与 SKU 无关。解锁卡上的 OpenCL-Benchmark 同样报告 1410 MHz 下有 70 个计算单元（4480 个核心，理论 FP32 性能为 12.634 TFLOPs/s）。

需要注意的是，35 个 TPC 是一个奇数：5 个活动 GPC 并不都拥有 8 个 TPC，这对经过收获分级的部件来说很正常。

## 熔丝裁剪与按晶片分级

熔丝裁剪是指在测试阶段烧断 OTP 熔丝，从而禁用有缺陷或多余的单元。170HX 完全通过熔丝和 STATUS 路径实现这一功能：**每个 CTRL_OPT 覆盖寄存器的读数都是 0**，拓扑报告自身的汇总行则是 `held back by CTRL_OPT: 0 TPC = 0 SM`。这说明 70 个 SM 已经是这些晶片的熔丝下限，其上不存在可以放宽的软件覆盖层。

| 寄存器 | 地址 | 作用 | 170HX 读数 |
|---|---|---|---|
| `OPT_GPC_DISABLE` | `0x00820350` | GPC 禁用掩码（熔丝） | 按晶片变化，置 3 位 |
| `STATUS_OPT_GPC` | `0x00820c1c` | 有效 GPC 掩码 | 始终镜像熔丝 |
| `OPT_GPC_DEFECTIVE` | `0x008205c4` | 哪些 GPC 确实损坏 | 某些卡为 `0x00` |
| `RING_ENUM_GPC` | `0x00120078` | 环上枚举出的 GPC | `5` |
| `CTRL_OPT_GPC` | `0x0082081c` | 软件熔丝裁剪覆盖 | `0x00000000` |
| `CTRL_OPT_FBIO` / `_FBPA` / `_FBP` | `0x00820814` / `0x00820818` / `0x00820938` | 同上，显存侧 | `0x00000000` |
| `CTRL_OPT_PERLINK` / `_PCIE_LANE` / `_NVLINK` | `0x00820820` / `0x0082082c` / `0x008209b8` | 同上 | `0x00000000` |
| `FUSE_EN_SW_OVERRIDE` | `0x00820040` | 是否启用 CTRL_OPT 层 | `0x00000000` |
| `gpcMask` | `0x00408970` | GR 侧 GPC 掩码 | `0xdc`，写入后会重新断言 |
| `OPT_PCIE_DEVIDA` | `0x008204d8` | SKU 身份熔丝 | 8 GB 卡报告为 `0x20c2`（见下方备注） |
| `OPT_SLT_REV` | `0x008204bc` | 插槽 / 测试修订版本 | 按晶片变化 |

**掩码按单张卡变化，而不是按 SKU 变化，也不会随驱动版本变化。** 三次独立调查共记录了 7 个不同的 `OPT_GPC_DISABLE` 值，其中 4 个来自同一天下午读取的 4 张卡；它们全部禁用了 3 个 GPC，合计都是 70 个 SM：

| `OPT_GPC_DISABLE` | 被禁用的 GPC | 卡 |
|---|---|---|
| `0x85` | 0、2、7 | 10 GB |
| `0x45` | 0、2、6 | 8 GB |
| `0x13` | 0、1、4 | 8 GB |
| `0xa8` | 3、5、7 | 10 GB |
| `0xd0` | 4、6、7 | 熔丝表卡 |
| `0x23` | 0、1、5 | 熔丝表卡 |
| `0x15` | 0、2、4 | 10 GB |

部分被禁用的 GPC 被标记为**物理完好**。在那张用于高安全写入实验的 8 GB 卡上，`OPT_GPC_DEFECTIVE` 读到 `0x00000000`，而 `OPT_GPC_DISABLE` 置了 3 位，这说明 3 个被禁用的 GPC 都是健康硅片，只是为了达到产品规格而被熔丝裁剪关闭。在一张 10 GB 卡上，`OPT_GPC_DEFECTIVE` = `0x81`（GPC 0 和 7 确实有缺陷），而 GPC 2 虽然被禁用，却没有被标记为有缺陷。

### 限制与分级的分界

对两张实体 170HX 卡进行完整的 120 个寄存器 diff 后发现，**107 个寄存器相同，13 个不同，而且这 13 个全部都是分级值**。这是目前关于该晶片最具实际操作价值的工具链结果：

- **产品线常量：每张 170HX 都相同，可以安全地硬编码到操作配方中：** 9 个速度选择熔丝（`FUSE_SS_DP` = `0x1`，其余 8 个 = `0x5`）、`FUSE_PCIE_GEN23_DIS` = `0x1`、`FUSE_PCIE_GEN3_DIS` = `0x1`、`FUSE_NVLINK_DIS` = `0x7`、`FBPA_CFG1_BROADCAST` = `0x02449000`、`FUSE_PCIE_DEVIDB` = `0x20c2`、`FUSE_ECC_EN` = `0x0`、`FUSE_EN_SW_OVERRIDE` = `0x0`。（120 个寄存器 diff 中的两张卡都是 10 GB，因此凡是按 SKU 而非按晶片变化的寄存器，在这份 diff 里看起来都会像常量。其中有两个就是这种情况：`FUSE_SKU_ID`（`0x00821060`）在 10 GB 卡上读到 `0x68`，在 8 GB 卡上读到 `0x80`；`FUSE_PCIE_DEVIDA`（`0x008204d8`）在 10 GB 卡上读到 `0x2082`，在 8 GB 卡上读到 `0x20c2`，而 `FUSE_PCIE_DEVIDB` 在两者上都是 `0x20c2`。DEVIDA 和 SKU_ID 都不能安全地硬编码，`lspci -nn` 仍然是最简单的 SKU 检测方法。）
- **按晶片变化、绝不能硬编码的值：** 所有熔丝裁剪掩码及其 STATUS 镜像、`FEAT_OVR_SM_SPD`（`0x0082381c`）、`FEAT_OVR_SM_SPD_1`（`0x00823820`）、`FEAT_OVR_QUADRO`（`0x00823808`）、`I1500_DATA`、`I1500_SHADOW_WDR`，以及每个 FBPA 的所有回读值。

正是由于存在这条分界，[算力解锁](../unlock/compute-throttle.md)才可以发布两个固定的魔法常量，同时在每张卡上都保持正确；也正因为如此，任何拿你的卡去对比“那个”出厂 SS0 值的工具，实际上都是在拿噪声做比较。

### 调查你自己的卡

只读调查工具 `ga100_topology_report.py`（v1 为 4848 字节；v2 为 8128 字节，并增加了 InfoROM 转储）会读取 `PMC_BOOT_0`、`OPT_GPC_DISABLE`、`STATUS_OPT_GPC`、`OPT_GPC_DEFECTIVE`、`RING_ENUM_GPC`、`PTOP_SCAL_NUM_GPCS`、`PBUS_SW_SCRATCH(1)`（`0x00001404`）、`0x00118f78`、`OPT_PCIE_DEVIDA`、`OPT_SLT_REV`，以及每个 GPC 的 OPT_DISABLE / RECONFIG / CTRL_OPT / STATUS / RECONF_OVR 组。至少有 4 位互不相关的研究者在两个 SKU 上运行过该工具，输出彼此一致。

> [!NOTE]
> **未解问题：缺失的 38 个 SM**
>
> 从 70 个 SM 增加到 A100 的 108 个，甚至晶片完整的 128 个，会是这张卡能获得的最大收益；而在 `OPT_GPC_DEFECTIVE` = 0 的卡上，被禁用的 GPC 已知是完好的硅片。截至目前找到的每条写入路径都会锁存结果。`FUSE_CTRL_OPT_TPC_GPC` 只能执行移除操作（即使对活动 TPC 做 OR 测试，也没有让计数下降）；在一次包含两个阳性对照、能够证明写入原语确实有效的实验中，对 `OPT_GPC_DISABLE`、`STATUS_OPT_GPC`、`OPT_TPC_GPC2`（`0x00820768`）和 `DIS_SW_OVR`（`0x00820084`）进行的高安全写入，回读值都没有变化；而通过 3 种不同方式强制设置 `gpcMask`（RM 结构体、向 `0x00408970` 写入主机 MMIO、将 GSP 固件中的 `andi` 修补为 `li a4,255`），虽然能让软件栈报告 8 个 GPC / 112 个 SM，但 `0x00408970` 每次回读仍是 `0xdc`，并且 `cuInit` 会段错误。尚未尝试的候选路径包括：通过静态熔丝裁剪掩码查询实现的 GSP-RPC 路径（类 `0x2080122a` / `0x2080122b`）、一次 GR 影子写入，或将写入原语移植到 PMU / GSP / FECS / GPCCS。参见[失败路线](../history/dead-ends.md)。

> [!WARNING]
> **实验性**
>
> 有一张实际流出的卡据报告曾被 CTRL_OPT 裁剪到 **56 个 SM**，而不是熔丝下限的 70 个；研究者夺回了 6 个 SM，达到 62 个，但启用剩余 TPC 后它们确实会失败。这被描述为目前见到的第一张经过算力裁剪的卡，但没有发布裁剪前后的寄存器转储。其他所有接受调查的卡都已经处于熔丝下限，在这种状态下 CTRL_OPT 不会造成额外损失。低于 70 个 SM 的情况应视为罕见现象，而不是正常情况。

## 显存分区与缓存层级

帧缓冲侧与图形侧分别进行熔丝裁剪。GA100 有 12 个 FBP，每个 FBP 包含 2 个 FBPA，因此共有 24 个 FBPA，每个宽 256 bit。每个 1024-bit HBM 接口实际上由 4 个 256-bit 通道组成，所以“部分堆叠启用”是真实存在的硬件状态，FBPA 掩码显示的是部分失效，而不是整堆干净地失败。

| 项目 | 8 GB SKU（`0x20c2`） | 10 GB SKU（`0x2082`） |
|---|---|---|
| 活动 FBPA | 24 个中的 16 个 | 24 个中的 20 个 |
| 活动 FBP | 12 个中的 8 个 | 12 个中的 10 个 |
| 显存总线宽度 | 4096-bit | 5120-bit |
| 出厂容量 | 8192 MiB | 10240 MiB |
| 解锁容量 | 65536 MiB | 40960 MiB |

这里的熔丝裁剪掩码同样按晶片变化。两张 10 GB 卡读取到的 `FUSE_FBPA_DISABLE`（`0x00820368`）、`FUSE_FBIO_DISABLE`（`0x0082036c`）、`STATUS_FBPA`（`0x00820c18`）和 `STATUS_OPT_FBIO`（`0x00820c14`）在一张卡上全都是 `0x0003c000`（关闭 FBPA 14 到 17），另一张卡上全都是 `0x000000c3`（关闭 FBPA 0、1、6、7），两张卡都保留了 20 个活动 FBPA。被禁用的 FBPA 不会从各自的 CSTATUS 寄存器返回实际值，而是返回 `0xbadf20xx` 哨兵值；这个哨兵会指出哪些 FBPA 已关闭：在禁用 FBPA 0、1、6、7 的卡上，读到的是 `0xbadf2010` 和 `0xbadf2013`；在禁用 FBPA 14 到 17 的卡上，读到的是 `0xbadf2017` 和 `0xbadf2018`。一张 8 GB 卡的转储逐个枚举了它的 12 个 FBP 半堆区域：FBP 1 和 4 被禁用，FBP 6 和 11 有缺陷，其余 8 个处于活动状态，因此得到 8 × 8 GB = 64 GB，这正是解锁可以达到的容量。完整细节见[显存子系统](memory-subsystem.md)和[显存几何布局](../unlock/memory-geometry.md)。

| 缓存层级 | 大小 | 依据 |
|---|---|---|
| 每个 SM 的 L1 / 共享内存 | 192 KB | GA100 架构规格 |
| L2 | 32 MB（`32768 KB`） | CUDA `deviceQuery` 加上独立的延迟尖峰微基准测试 |
| 完整 A100 的 L2 | 40 MB | 用于对比 |
| OpenCL 全局缓存 / 本地内存 | 1960 KB / 48 KB | 解锁卡上的 OpenCL-Benchmark |

> [!NOTE]
> **存在争议**
>
> TechPowerUp 将 170HX 的 L2 列为 8 MB。但运行时 `deviceQuery` 报告的 32768 KB，以及独立的指针追逐延迟测量，都指向 32 MB，因此本维基采用 32 MB。现有资料中没有来源能够解释两者的差异；如果有一条已发布的延迟 / 带宽曲线，显示工作集在哪个位置突然下降，就可以解决这个问题。还要注意，正确的 TechPowerUp 条目是 `gpu-specs/cmp-170hx-8-gb.c3830`；较旧的 `c3824` URL 现在会重定向到一张 AMD 卡。

这款部件的 HBM 带宽**不受限制**，解锁也不会改变它（同一张卡的 A/B 测试在 256 MB 工作集下测得出厂状态 1592 GB/s、改装状态 1599 GB/s，比例为 1.0x；同一张测试表中 FP32 则提升了 30.7x）。理论峰值是 5120-bit 总线、1215 MHz DDR 下的 1555.2 GB/s（= 1448.4 GiB/s）。根据工具和访问模式不同，实测值在 **1305.86 到 1600 GB/s** 之间，没有唯一的标准值；参见[性能](../operations/performance.md)。

## 计算能力与指令集

计算能力 8.0（`sm_80`）决定了这块晶片能做什么、不能做什么，与任何熔丝状态都无关：

- **每个 SM 有 64 条 FP32 通道**，每个 SM 有 64 个 warp，warp 大小为 32。FP64 遵循 GA100 的 1:2 比例；非张量 FP16 相对于 FP32 为 4:1。这在架构上很不寻常，也是锁定卡已经可以用于 LLM token 生成的原因。
- **280 个第三代 Tensor Core**（每个 SM 4 个）、280 个 TMU、128 个 ROP。Tensor Core 确实存在且可以使用，并没有被熔丝裁剪禁用：解锁卡实测 FP16 Tensor 性能为 158.7 到 190 TFLOPS，BF16 Tensor 性能为 164.4 到 192.7 TFLOPS。
- **没有 FP8，也没有 NVFP4 硬件路径。** 这些功能需要 `sm_89`+ / `sm_120`。在这张卡上枚举受支持 MMA 形状的工具将 `mma_mxf8mxf8f32_16_8_32` 和 `mma_f8f8f16/f32_16_8_32` 列为不支持，这符合 Ampere 的预期。INT8、INT4 和 INT1 在硬件中原生支持，不过 INT1 与 INT8 共用 XNOR-popcount 路径，没有专用单元。
- 对推理而言，实际影响是：`sm_80` 不支持 FP8 KV 缓存，因此 KV 必须使用 BF16。

## 存在、已被熔丝裁剪禁用和缺失的引擎

| 引擎 / 功能 | 170HX 上的状态 | 证据 |
|---|---|---|
| CUDA 核心、Tensor Core | 存在且可用，出厂状态下发射速率受节流 | 参见[算力节流](../unlock/compute-throttle.md) |
| FP64 单元 | 存在，由解锁恢复 | 按 1:2 比例实测 |
| **NVENC** | **缺失。** GA100 晶片通常不带视频编码器 | 频道内报告，与晶片功能集一致 |
| **NVDEC** | 晶片级：根据规格数据库，有 5 个第四代 NVDEC 实例。驱动级：该 SKU 不会暴露 NVDEC。探测 NVDEC falcon 邮箱 `0x00830040` 时返回 `0xbadf1100`，即被阻挡或只读 | 规格数据库，中等置信度；falcon 探测 |
| **显示引擎 / 输出** | **缺失。** 没有任何显示输出，`Slot Width: IGP`，也没有 DirectX / Vulkan / OpenGL 暴露 | 规格数据库和每一次 `lspci` 捕获；后者将设备命名为 `3D controller` |
| **NVLink** | **已被熔丝裁剪禁用。** `FUSE_NVLINK_DIS` / `STATUS_OPT_NVLINK`（`0x00820db8`）= `0x7`；板上也缺少 NVLink 接口 IC。`0x00823800`-`0x0082382c` 块中没有 NVLink 寄存器，任何分支都不包含 NVLink 代码 | 熔丝读取和拆解；参见[NVLink 硬件](nvlink-hardware.md) |
| **ECC** | **已被熔丝裁剪禁用。** `FUSE_ECC_EN` = `0x0`，没有遥测，也没有已知的启用手段。`FEAT_READOUT_0` 的高位 ECC 状态半字节读为 0，与熔丝状态一致 | 参见[ECC 前沿](../frontier/ecc.md) |
| **P2P** | 缺失。所有发布版代码树和分支代码树中都没有 P2P 代码；唯一的 MIG 档位报告 `P2P: No` | 参见[P2P 前沿](../frontier/p2p.md) |
| **MIG** | 硬件支持（`0x00820840` 的第 0 位为启用位），但只暴露一个档位 `1g.64gb`，因此 GPU 实际上无法进行分区 | 社区发现，发布版代码中没有相关内容 |
| **Resizable BAR** | 存在，但限制为 64 MiB | `lspci` 能力 `[bb0]` |
| **FLR** | 存在（DevCap 中有 `FLReset+`），并且是每个解锁工具框架正常工作的必要条件 | `lspci -vvv` |

> [!NOTE]
> **未解问题：NVENC 是已被熔丝裁剪禁用，还是根本没有制造出来？**
>
> 频道内的原话是：“nvenc is disabled ... idr if it's fused off or if it's fuse gated but it's not available by default if it has the hardware.”（NVENC 已被禁用……不确定是熔丝关闭，还是由熔丝门控；即使存在硬件，默认也不可用。）目前没有人报告过 NVENC 会话成功运行，也没有人提出解锁路径。显而易见的下一步，是采用破解算力节流时使用的同一种差分方法：分别读取 170HX 与 A100 或 DRIVE A100 对照部件在 `0x00820xxx` 块中的 NVENC 相关 `OPT_*_DISABLE` 熔丝，然后进行 diff。在完成这项工作之前，应假定这张卡没有硬件编码器。

## 为什么这块晶片对解锁很重要

正是这块特定硅片的 3 个属性，让整个项目成为可能：

1. **主清除熔丝没有烧断。** `OPT_FEATURE_FUSES_OVERRIDE_DISABLE`（`0x008203f0`）读为 `0x00000000`。如果它已经烧断，每个功能覆盖都会被永久锁定，也就不会存在任何软件路径。
2. **限制熔丝是产品线常量，而不是按晶片分级的值。** 一套操作配方就能适用于每张卡。
3. **DRIVE A100（`0x20bb`、PG199、`GA100-550F-A1`）是一个干净的阴性对照。** 两块实体板都与 170HX 一样关闭了 NVLink，也具有 `EN_SW_OVERRIDE` = 0 / `DIS_SW_OVR` = 1 状态；但它们的 9 个速度选择熔丝全部读为 `0x00000000`，`FEATURE_READOUT_1` = `0x00000000`，并且在 96 个 SM 上拥有完整算力。正是这个单变量隔离证明了：`OPT_SM_SPEED_SELECT` 熔丝块，而且只有它，是算力限制的来源。

完整熔丝图参见[熔丝与 OTP](fuses-and-otp.md)，关于如何触达覆盖路径，参见[算力节流](../unlock/compute-throttle.md)。
