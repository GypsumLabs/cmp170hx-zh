# 硬件概述：完整规格

**本页涵盖内容：** NVIDIA CMP 170HX 的所有已确立规格，分别列出两种 SKU 的出厂状态和解锁状态，方便并排对比。如果某个数据存在争议、会因具体卡片而变化，或从未经过测量，本页会明确说明，而不是擅自选定一个数值。

一句话概括：CMP 170HX 使用 **GA100** 晶片，与 A100 是同一颗晶片；两种 **SKU** 都具备 70 个 SM、4480 个 CUDA 核心，计算能力为 8.0。它的限制来自四套彼此独立的机制，背后也有四个不同的原因：OTP 熔丝设置的 SM 发射速率节流（已通过软件解除）、跳线选择的显存几何布局（已通过软件解除）、PCIe **速度**上限（仅在未发布分支中通过软件解除），以及由 PCB 缺件造成、只能用烙铁修复的 PCIe **位宽**上限。NVLink 和 ECC 都已通过熔丝关闭，目前没有已知的解除手段。板级是否还额外缺少 NVLink 组件，仍未有定论。

> [!NOTE]
> **对现有社区维基的更正**
>
> 下面列出三个广泛流传的错误，并用证据加以纠正。
>
> 1. **SM 数量。** 8 GB 和 10 GB 两种 SKU 都准确暴露 **70 个 SM / 4480 个 CUDA 核心**。这一点由同时持有两种 SKU 的测试者验证，也由一次八卡枚举结果验证：8 个设备全部报告 `cu: 70`；此外还有四份独立的拓扑报告提供支持。任何给 10 GB 卡写出不同 SM 数量，或与自身备注相矛盾的表格，都是错误的。
> 2. **“PCIe Gen 1 x4、固件锁定”只说对了一半。** *速度*上限由固件和熔丝共同控制，已经通过软件解除。*位宽*限制完全不是固件造成的：16 条通道中有 12 条出厂时就没有安装交流耦合电容。通道熔丝保持干净（`OPT_PCIE_LANE_DISABLE` = `0x00000000`）；一张出厂未改装、运行 Gen2 代码的卡报告 `LnkCap: Speed 5GT/s, Width x16`，但 `LnkSta` 仍然显示 `Width x4 (downgraded)`，这证明限制来自板级硬件。还要注意，Gen2 从未在 VM 直通环境或 Thunderbolt 连接中复现。
> 3. **“解锁后的 FP64 是 6.44 TFLOPS”和“11.6 TFLOPS”**之间的差异，是非张量路径与张量路径的混淆，并不矛盾。两个数字都是真实的。参见[算力吞吐（实测）](#compute-throughput-measured)。

### SM 裁剪按卡片区分，而不是按 SKU 区分

每一张被调查的 170HX 都枚举出 5 个 GPC / 35 个 TPC / 70 个 SM，而 70 已经是熔丝设定的下限：对典型卡而言，`CTRL_OPT` 不会带来任何额外 SM。具体禁用哪些 GPC 取决于单张卡，不会随驱动版本变化。以下是同一个下午读取的四张卡：

| `OPT_GPC_DISABLE`（`0x820350`） | 关闭的 GPC | SKU |
|---|---|---|
| `0x85` | 0、2、7 | 10 GB |
| `0x45` | 0、2、6 | 8 GB |
| `0x13` | 0、1、4 | 8 GB |
| `0xa8` | 3、5、7 | 10 GB |

`STATUS_OPT_GPC`（`0x820c1c`）始终与它保持一致。关键在于，在几张禁用掩码设置了三个 bit 的卡上，`OPT_GPC_DEFECTIVE`（`0x8205c4`）读数为 `0x00000000`，说明这些 GPC 是物理上完好的晶片，只是为了达到产品规格而被禁用。这里理论上仍有可挖掘的空间，但目前找到的所有写入路径都会被锁存：对 `0x820350`、`0x820c1c`、`0x820768` 和 `0x820084` 进行 HS 特权写入后，回读值都不变；通过三种不同方式强制设置 `gpcMask`（`0x408970`）后，它仍会重新断言为 `0xdc`，同时 `cuInit` 发生段错误。市面上有一张罕见的卡曾被 `CTRL_OPT` 扫到低于熔丝下限的 56 个 SM，并成功恢复了 6 个 SM。参见[GA100 晶片](ga100-silicon.md)和[熔丝与 OTP](fuses-and-otp.md)。

> [!NOTE]
> **未解问题：8 GB 卡的真实 HBM 时钟**
>
> 目前流传着三种计法，而且没有一种得到过统一解释。规格数据库和一次 2023 年的 `deviceQuery` 结果给出 **1458 MHz**（报告值是 729 MHz，按惯例翻倍），这意味着理论上限为 1492.99 GB/s。2026-07-27 的一次直接测量给出 **1728 MHz**，对应 3.456 Gbps/pin 和 1769 GB/s 的理论上限。第三种说法把 8 GB 卡的时钟写成 398 MHz，而 A100 为 304 MHz，乘以四后得到 **1592** 和 1216 MHz。实测交付读取带宽为 1679-1699 GB/s，排除了那次运行使用 1458 MHz 的可能，但无法在 1592 和 1728 之间做出判断。要彻底解决这个问题，需要公布分频链的原始 FBPA PLL 寄存器读数。

> [!CAUTION]
> **一次运行成功完成，并不能证明时钟偏移是安全的**
>
> 在调优参考卡的 1400 MHz 上限下，+250 MHz 通过了三次完整显存模式扫描且没有错误，+300 MHz 通过了四次；但 +325 MHz **在没有崩溃的情况下静默损坏了显存数据**：三次扫描依次返回 6、3、0 个错误。该卡的安全窗口只有一个 25 MHz 步进，超过窗口后，故障表现是错误数据而不是崩溃。每个候选设置都应以四次完整显存扫描作为放行条件，而不是两次；还要注意，不同卡之间存在晶片差异，在一个序列号上验证过的偏移，对另一张卡不能说明任何问题。详情和完整故障矩阵见[调优](../operations/tuning.md)。

## 显存：按 SKU 区分的出厂与解锁状态

| 量 | 8 GB SKU | 10 GB SKU |
|---|---|---|
| PCI ID | `10de:20c2`（`0x20C2`） | `10de:2082`（`0x2082`） |
| 显存类型 | HBM2e（SK Hynix） | HBM2（Samsung）。厂商划分是根据时钟、稳定性和一次 GPU-Z 读取推断的，不是根据封装标记判断；参见[板卡与变体](board-and-variants.md) |
| 出厂报告容量 | 8192 MiB（CUDA 报告 7961 MB） | 10240 MiB |
| **解锁容量** | **65536 MiB（64 GB）** | **40960 MiB（40 GB）** |
| 活动 FBPA / FBP | 16 / 8 | 20 / 10 |
| 总线宽度 | **4096-bit** | **5120-bit** |
| 出厂 CFG1 `0x009a0204` | `0x02449000` | `0x02449000`（两种 SKU 相同） |
| 解锁 CFG1 | `0x02779000` | `0x02669000` |
| 出厂 LMR `0x00100ce0` | `0x00000208` | `0x00000288` |
| 解锁 LMR | `0x0000020B` | `0x0000028A` |
| `targetFbBytes` / `fb_length` | `0x0000001000000000`（64 GiB） | `0x0000000A00000000`（40 GiB） |
| 出厂 `CSTATUS_RAMAMOUNT` | `0x200`（每个 FBPA 512 MiB） | `0x200` |
| 解锁 `CSTATUS_RAMAMOUNT` | `0x1000`（每个 FBPA 4096 MiB） | `0x800`（每个 FBPA 2048 MiB） |
| 被熔丝裁剪的 FB 单元 | 2 个 FBP 有缺陷，2 个被禁用（检查过一张卡） | `OPT_FBPA_DISABLE` = `0xc3`；fbpa00/01/06/07 被关闭 |
| ECC | 已通过熔丝关闭 | 已通过熔丝关闭 |

这些解锁常量并非凭空捏造：`0x02779000` 恰好是 A100 PCIe 80 GB 的出厂 CFG1 字，而 `0x02669000` 是 A100 PCIe 40 GB 和 A100 SXM4 40 GB 的出厂字。解锁恢复了真正的 A100 几何布局。LMR 将总帧缓冲大小编码为 `MiB = MAG[9:4] << SCALE[3:0]`，每个 FBPA 的容量相应为 `2^(SCALE+1)` MiB。完整说明见[显存几何布局](../unlock/memory-geometry.md)和[显存子系统](memory-subsystem.md)。

> [!NOTE]
> **显存几何布局无法挺过 FLR 或断电；算力解锁可以**
>
> SS0、SS1 和 `0x00823804` 可以挺过 FLR；CFG1/LMR 几何布局重写则不能。这种不对称性解释了为什么算力解锁比显存解锁更早发布，也解释了为什么下面的 DtoD 带宽条目会把“no FLR”列为明确条件。

> [!WARNING]
> **80 GB 配置不是第三种选择**
>
> 实验性的 `80` 分支在自己的 README 中声称可以工作，但实际并非如此。它用 LMR `0x0000028A` 和 `fb_length` `0x0000001400000000` 配置 CFG1 `0x02779000`，三个层级之间存在三方不一致，这是它恰好在 40 GiB 处折叠的最佳解释（`constants.yaml` 中的 `0x0000028B` / `81920` 只是 `build.sh` 从不读取的惰性元数据）。一个净室逆向脚本写入一致的 `LMR 0x0000028B` 后可以消除折叠，但该脚本没有随项目发布，而且运行约一个 CUDA 上下文后仍会丢失设备。卡片会报告约 81920 MiB，77 GiB 的连续填充测试也能通过，但访问超过约 40 GB 的内核会导致 GPU 致命丢失，且与功耗上限无关。报告的 Xid 代码包括 Xid 31（有人称其为无害）以及 CUDA 显存测试后的 Xid 154；最常见的症状是卡死。单独将 Xid 31 视为*该故障*的特征，是旁观者提出的说法，发生故障的卡片操作者并未证实这一点。每次触发后只能保留一个 CUDA 上下文。参见[80 GB 前沿页](../frontier/80gb.md)。

## 算力吞吐（实测）

以下数据均来自出厂时钟下的锁定和解锁状态。解锁只是一次寄存器写入，不会改变时钟，因此除非另有说明，下面的所有数值都是出厂时钟下的结果。

| 数据类型 / 路径 | 锁定 | 解锁 | 增益 |
|---|---|---|---|
| FP32 非张量（FFMA） | 0.30 - 0.41 TFLOPS | **12.2 - 12.8 TFLOPS** | 26x - 32x |
| FP32 理论值 | n/a | 12.63 TFLOPS（4480 × 2 × 1410 MHz） | 实测约达到理论值的 99% |
| FP32 非 FMA（对照） | 4.31 - 6.29 TFLOPS | 不变 | 从未受到节流 |
| FP64 非张量 | 约 0.20 TF/s | **6.2 - 6.3 TFLOPS** | FP32 的一半，即完整 GA100 的速率 |
| FP64 张量 | n/a | **11.6 - 12.9 TFLOPS** | 约为非张量速率的两倍 |
| TF32 张量 | 2.96 - 3.21 TFLOPS | **79 - 94 TFLOPS** | 15x - 28x；所有数据类型中差距最大 |
| FP16 张量 | 6.52 TF/s | **158.7 - 190 TFLOPS** | 较高的数值使用 fp16 累加 |
| BF16 张量 | 6.40 TF/s | **164.4 - 192.7 TFLOPS** | 理论上限为 2048 × 70 × 1410 MHz = 202.1 TFLOPS |
| FP16 标量（非张量） | 约 42 - 50 TFLOPS | 不变 | **从未受到节流**，锁定卡也是如此。GA100 执行 16 位 hfma 时，速率是 FP32 的 4 倍 |
| INT32 | 约 12.5 TIOPS | 不变 | 约为 A100 的 20 TIOPS 的 62.5% |
| INT8，张量 MMA 微基准测试 | 1.60 TOPS | 335.0 - 335.6 TOPS | 直接使用 `mma.s8s8s32` |
| INT8，库 / 服务路径 | 1.63 TOP/s | **44.1 TOPS，仍受门控** | 比 FP16 *慢*约 3.7 倍，而 A100 在该路径上约快 2 倍 |
| INT4 张量 MMA | 11.55 TOP/s | 320.2 TOPS | |
| INT1 | 46.16 TOP/s | 约 1039 TOP/s | 超过 1 PetaOP/s |
| FP8 / FP6 / FP4 | n/a | **硬件不支持** | 这符合 `sm_80` 的预期；MMA 扫描会将它们逐一列为不支持 |

INT8 结果在实际使用中的含义值得明确说明：进行推理时，应使用 W4A16（AWQ 或 GPTQ，即 INT4 权重配 BF16 激活），完全避开 W8A8；KV 缓存必须使用 BF16，因为 `sm_80` 不支持 FP8 KV。参见[LLM 推理](../operations/llm-inference.md)和[性能](../operations/performance.md)。

> [!NOTE]
> **`deviceQuery` 报告的 8960 个核心和 25.27 TFLOPS 是错误的**
>
> `deviceQuery` 会打印 `Total SPs: 8960 (70 MPs x 128 SPs/MP)` 和 25267.20 GFlops。这个差异恰好是 2 倍，与工具错误地使用计算能力 8.6 中“每个 SM 有 128 条 FP32 通道”的数据，而不是 GA100 的 64 条相吻合。算术计算和所有实测结果都支持 4480 个核心以及约 12.6 TFLOPS。

| Gen1 x16（仅电容改装） | 2.88 GB/s，稳定平坦且无错误 | 中等；标称值约为 4 GB/s，差距归因于 PCIe 1.1 信令开销 |
| Gen2 x16 | 6.63 - 6.67 GB/s | **中等：一台设备、一天（2026-07-26）、一次捕获。** Gen2 x16 的稳定性尚未确立 |

**为什么位宽是 x4：** 16 条通道中的 12 条（通道 4-15）出厂时没有安装交流耦合电容。每个差分对需要 2 个电容，因此总共缺少 24 个元件，设计标号位于 `C1100`-`C1350` 范围内。规格为 **0402、220 nF（0.22 µF）、X7R、16 V 或更高**，来源是 NVIDIA A100 GA100-883 参考原理图 P1001-B02 第 3 页（“IO: PCIe CONNECTOR”）；已确认可用的元件是 Samsung `CL05B224KO5NNNC`。（介质是 X7R，“XR7”是常见的字母颠倒写法。）只补装 24 个电容中的 12 个会得到 x8，因为 PCIe 位宽协商会退回到下一个合法位宽；改装后得到 x8，说明焊接不完整或出现了桥接，并不是另一种独立的硬件限制。通道熔丝保持干净，因此位宽没有任何可编程部分。参见[物理改装](../operations/physical-mods.md)。

**为什么速度是 Gen1：** 在两种 170HX SKU 上探测到的两个熔丝影子都是已烧断状态，而在另外十二个被探测的 Ampere 部件上都是干净的：`FUSE_PCIE_GEN23_DIS`（`0x0082057c`）= `0x00000001`，`FUSE_PCIE_GEN3_DIS`（`0x00820580`）= `0x00000001`。`FUSE_PCIE_MAGIC_D`（`0x00820520`）读为 `0x16680000`，其中 bit 25（`GEN4_SPEED_DISABLED`）已置位；DRIVE GA100 参考部件的读数则为 `0x00200000`。值得注意的是，即使 `OPT_GEN23` 从未被清除，Gen2 解锁仍然有效：每次尝试写入它都会在晶片上失败，真正起作用的是 CYA_0 / LINK_CONFIG_0 / XP3G / PRIV_MISC_1 覆盖。Gen3 和 Gen4 仍未实现：Gen3 的*能力声明*已经可以工作，但 `LnkSta` 从未脱离 2.5 GT/s。参见[PCIe 子系统](pcie-subsystem.md)、[Gen2](../unlock/pcie-gen2.md)和[Gen3/Gen4](../frontier/pcie-gen3-gen4.md)。

> [!WARNING]
> **实验性：Gen2 不在发布产品中**
>
> 发布版 `master` 只包含补丁 `0001` 至 `0006`，`constants.yaml` 中没有 `pcie:` 块，其“What Gets Unlocked”表只有三行，也没有 PCIe 条目。`0007-pcie-gen2.patch` 存在于 `debug-gen2`、`Gen2`、`far` 和 `deced` 分支；`0008-pcie-gen2-probe-retrain.patch` 存在于 `Gen2`、`far` 和 `deced` 分支。两个补丁都没有合并。Gen2 在实际使用中也不是确定性的，在 VM 直通下无法工作，通过 Thunderbolt 3 扩展坞时会完全失败（Oculink 可以工作，因为它本质上就是一条直连转接线）。

## NVLink、P2P 和其他缺失功能

| 功能 | 状态 | 原因 |
|---|---|---|
| NVLink | **已通过熔丝关闭** | `FUSE_NVLINK_DIS` `0x00820684` = `0x00000007`，`STATUS_OPT_NVLINK` `0x00820DB8` = `0x00000007`，与 Drive A100 部件一致。仅这一点就足以排除 NVLink。板侧是否安装了 NVLink 组件仍**没有定论**：两种结论都有直接证据；参见[NVLink 硬件](nvlink-hardware.md)。`0x00823800`-`0x0082382C` 区块中没有 NVLink 寄存器，任何分支中也没有 NVLink 代码 |
| 点对点传输（P2P） | 这张卡不具备 | 从未演示成功；尚未判断是熔丝关闭还是由驱动门控 |
| ECC | 已通过熔丝关闭 | `FBPA_ECC_CTRL`（`0x009a0470`）= 0，且 `MASTER_EN` 为只读；没有遥测；名为 `ecc` 的分支完全没有 ECC 代码 |
| NVENC | 不可用 | 不清楚是已通过熔丝关闭，还是由其他熔丝门控；没有报告过成功运行的 NVENC 会话 |
| MIG | **可以启用，但无法分区** | `0x00820840` 的 bit 0 可以将其打开，并且状态报告为持久化；但只暴露一个 profile（`1g.64gb`、63.00 GiB、70 个 SM、P2P No），因此 GPU 实际上无法细分；`-cgi 9,3g.20gb -C` 返回 `Invalid Argument`。不在发布树中 |
| Resizable BAR | **已声明但不起作用** | `[bb0 v1]` 中存在该能力；每个 BAR 恰好声明一个受支持的大小，而无论报告的帧缓冲大小是多少，BAR1 都保持 64 MiB。“ReBAR 需要 Gen3”的质疑已经被反驳。在 Gen2 训练的卡上尚未测试 |

## 供电与电气

| 量 | 值 |
|---|---|
| TDP / 默认功耗上限 | **250 W**（出厂 VBIOS：默认值 = 最大值） |
| 出厂 VBIOS 的功耗上限范围 | 最低 100 W，最高 250 W。`nvidia-smi -pl` 可以工作，只是出厂值之上没有余量 |
| 使用 300 W OC VBIOS 时的功耗上限 | 最高 300 W；一次 30 分钟的 `gpu_burn` 记录到 `POW 278 / 300 W`。适用于 **8 GB** SKU；本资料中没有人验证过它与 10 GB 卡上的解锁同时使用 |
| 插槽功耗上限（`DevCap`） | **75 W**；超过这一数值的功耗都来自辅助接口 |
| 外部接口 | **一个 8-pin EPS（CPU 式）**插座，提供两条内部 12 V 轨：`12V_EXT1` 和 `12V_EXT2`。额定功率为 300 W。随卡附带一条双 8-pin PCIe 转 8-pin EPS 的 Y 形转接线 |
| 空转功耗 | 27 - 46 W，强烈取决于温度和驻留状态。驻留的 CUDA 上下文会使功耗从约 33 W 升至约 45 W |
| 性能状态 | **只有 P0。** `nvidia-pstated` 返回 `NVAPI_ERROR`；双 P 状态分支没有产生任何变化 |
| 电源轨 | `3V3_PEX`（通过 LDO 转为 1.8 V）、`12V_PEX`（通过 MP1475 转为 5 V，通过 MP2988 转为 1.35 V 和 PEXVDD，通过第二个 MP1475 转为 HBMVPP 2.5 V）、`12V_EXT1`/`12V_EXT2`（通过 MP2988 多相方案为 NVVDD 1.0 V 核心和 HBMVDD 供电） |
| VRM 贴装情况 | **相较 A100 有所减配。** 每侧缺少 3 个功率 MOSFET 和电感；A100 40 GB 每侧缺 1 个，A100 80 GB 则没有缺件。另一份对比将其估算为约 20 相中的 6 相。有人报告 8 GB 卡解锁至 64 GB 不需要修改 VRM |

> [!CAUTION]
> **8-pin 插座是 EPS，不是 PCIe**
>
> 8-pin PCIe 线缆与卡上的 EPS 插座键位不同，只能强行插入；两种接口的部分引脚还交换了 12 V 和地线。强行插入**会损坏显卡**。请使用随卡附带的转接线：接一条线时预算为 150 W，两条都接时为 300 W。
> 模组电源的线缆同样具有厂商专用的引脚定义，模组侧没有统一标准；跨品牌复用线缆可能损坏硬件。

按工作负载测得的实际功耗远低于标签所暗示的数值，这是该部件的特性，而不是故障：常规 FP32 烤机只能达到约 60 W，张量 `gpu_burn` 约为 75 W；整数和显存受限的工作负载则能达到 160+ W，持续的实际负载为 200-280 W。**绝不要用 FP32 烤机来验证这张卡的稳定性或散热。** 将功耗上限从 250 W 提高到 300 W 后，在核心和显存温度都低于 65 C 时，BF16 性能测得提升 **+2.8%**。完整细节见[板载供电](power-delivery.md)和[供电与 PSU](../operations/power-and-psu.md)。

## 外形、散热与热限制

| 属性 | 值 |
|---|---|
| 外形 | 全长双槽 PCIe 插卡 |
| 厚度 | 约 40 mm / 1.57 in（双槽）；卡体与 PCIe 边缘连接器之间约有 5-6 mm 间隙 |
| PCB | 几乎完全、至少也是高度接近 A100 40 GiB 板卡。A100 水冷头和 A100 导流罩在物理上都可以安装 |
| 散热器 | **全被动**：裸露散热片，没有风扇，设计依靠高转速服务器机箱风扇提供强制风冷。每次捕获中，`nvidia-smi` 都报告 `Fan Speed : N/A` |
| 发布的 CFM / 静压 / dBA / 鳍片间距 | **没有这类数据。** 任何气流数值都必须来自社区测量 |
| GPU 关机温度 | 98 C |
| GPU 降速温度 | 95 C |
| GPU 最大工作温度 | 85 C |
| 显存最大工作温度 | 95 C |
| 实际节流起始温度 | 约 80 C（一位测试者的遥测数据；社区设计目标确定为核心 70 C / 显存热点 75-76 C） |

> [!CAUTION]
> **GA100 存在由漏电驱动的热失控现象**
>
> 结温升高会增加 CMOS 漏电，漏电增加又会提高功耗，最终进一步推高温度。这一现象曾在一张安装了水冷头却没有注入冷却液、进行干跑测试的卡上被亲眼观察到：空转功耗从 **40 W 上升到 80 C 时的 60 W，并且仍在继续增加**。如果散热完全失效，该部件不会稳定在节流点，而是会继续超过这一温度。如果曾经在没有冷却液的情况下让这张卡干跑，请在 5 分钟内断电。带实测结果的散热方案对比见[散热](../operations/cooling.md)。

## 对比锚点

| 部件 | SM / 核心 | 显存 | 总线 | 备注 |
|---|---|---|---|---|
| CMP 170HX 8 GB，解锁 | 70 / 4480 | 64 GB HBM2e | 4096-bit | 本卡 |
| CMP 170HX 10 GB，解锁 | 70 / 4480 | 40 GB HBM2 | 5120-bit | 同一颗晶片，不同的熔丝裁剪结果 |
| A100 PCIe 40 GB | 108 / 6912 | 40 GB | 5120-bit | 出厂 CFG1 `0x02669000` |
| A100 PCIe 80 GB | 108 / 6912 | 80 GB | 5120-bit | 出厂 CFG1 `0x02779000`，LMR `0x0000028b` |
| A100 32 GB Drive（PG199） | 96 | 32 GB | 4096-bit | 全部 9 个速度选择熔丝都读为 0；与 170HX 一样关闭了 NVLink |
| CMP 90HX | GA102、GDDR6X | n/a | n/a | 完全不同的晶片；没有隐藏显存，也没有 NVLink 金手指 |

解锁后的卡相当于 A100 的多少性能，至今没有在两种部件上使用匹配基准测试得出定论。现有估计大多集中在 70-75%，大致符合 70/108 的 SM 比例，但两个方向上都有离群值。从规格来看，解锁后的 64 GB 卡在带宽、容量以及 BF16/FP16 吞吐方面可与 AMD Instinct MI210 相比；互连能力则是 AMD 明显占优的方面。
