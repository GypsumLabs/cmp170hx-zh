# 物理改装

**本页涵盖内容。** CMP 170HX 所有已有记录的硬件改装：恢复 x16 链路位宽的 PCIe 交流耦合电容改装、让改装成功所需的焊接技术和工具、结果验证方法、拆解顺序、散热和水冷头改装、电源连接器情况、跳线电阻，以及这张卡上烙铁无论如何都无法修复的部分。

结论先说：**CMP 170HX 之所以以 PCIe x4 训练，是因为出厂时 16 条通道中有 12 条没有贴装交流耦合电容。手工焊上缺失的 24 颗 0402、220 nF、X7R 电容，就能恢复完整的 x16 链路，完全不需要任何软件补丁。** 这是一次从新手到爱好者级别的返工；已有报告称，手工改装每张卡约需 20 分钟。

> [!WARNING]
> **位宽不是速度**
>
> 电容改装**只改变链路位宽**，从不会改变 PCIe 代数。一张装了电容、但没有安装解锁器的卡，会报告 **PCIe 1.0 下的 x16**。反过来，无论是否焊接电容，解锁器都能让卡运行在 Gen2（5 GT/s）；只有没有安装解锁器的卡才会报告 Gen1。这两个维度彼此独立，绝不能混为一谈。速度部分请参见[PCIe Gen2](../unlock/pcie-gen2.md)。

## 为什么 16 条通道中有 12 条失效

CMP 170HX 的 PCB 是 NVIDIA A100 40 GB PCIe 参考设计，只是有意删去了部分元件。板上每个参考编号都与泄露的 NVIDIA Tesla A100 电气原理图 `NVIDIA-A100-GA100-883-P1001-B02-Rev-A.pdf`（PG100/PG101 系列）相匹配。不同卡的金手指上方丝印分别为 `180-11001-DAAA-B15`、`180-11001-DAAA-B35` 和 `180-11001-DAAA-045`，属于同一系列，只是修订字段不同。参见[板卡与变体](../hardware/board-and-variants.md)。

删去的部分包括未贴装的 VRM 相位、缺失的 NVLink 接口 IC、缺失的安全模块区域，以及关键的**通道 4 到 15 上缺失的 PCIe 交流耦合电容**。走线已经布置在 PCB 上，缺少的只是元件本身。NVIDIA 恰好只贴装了这张卡原本计划使用的 4 条通道。

这是板级元件缺失，不是熔丝问题，也不是固件设置问题。在所有被探测过的 170HX 上，PCIe 通道熔丝都处于未熔断状态：

| 熔丝 | 地址 | 170HX 值 | 含义 |
|---|---|---|---|
| `OPT_PCIE_LANE_DISABLE` | `0x00820394` | `0x00000000` | 没有通道被熔丝裁剪禁用 |
| `CTRL_OPT_PCIE_LANE` | `0x0082082c` | `0x00000000` | 没有启用通道覆盖 |
| `STATUS_OPT_PCIE_LANE` | `0x00820c2c` | `0x00000000` | 晶片报告完整位宽可用 |

链路状态寄存器也说明了同样的情况。出厂状态下，`lspci` 在能力字段中宣告 x16，却在状态字段中协商为 x4：

```text
LnkCap:  Port #0, Speed 2.5GT/s, Width x16, ASPM not supported
LnkSta:  Speed 2.5GT/s, Width x4 (downgraded)
LnkCap2: Supported Link Speeds: 2.5GT/s
```

位宽字段中的 `(downgraded)` 就是关键线索：端点宣告的能力是 x16，却只能以 x4 训练，这正是 12 条通道存在物理层断路时会出现的结果。还有一项独立证据来自一张运行 Gen2 代码、但没有做硬件改装的 8 GB 卡：它报告 `LnkCap: Speed 5GT/s, Width x16`，同时仍显示 `LnkSta: Speed 5GT/s, Width x4 (downgraded)`。软件改变了速度，却无法改变位宽；即使主机端口本身支持 x16，这张卡仍然只能以 x4 训练。

### 替代品

这项改装对 100 nF 到 220 nF 的一般去耦类元件都有一定容忍度。一位测试者报告 `100 nF 16 V X7R` 元件可以工作；另一位直接从报废主板上拆下等效的 0402 元件使用。这两条都只是单一的一手报告。如果手头有正确的 220 nF 元件，就应当优先使用它：替代品的证据很少，而边缘状态的交流耦合网络在训练时会失败，表现上无法与焊接不良区分。

## 焊接技术

这是几位职业焊接人员综合判断后的共识，其中包括一位明确撤回相反观点的人。

| 参数 | 建议 | 置信度 |
|---|---|---|
| 焊锡合金 | **60/40 含铅焊锡** | 高 |
| 助焊剂 | 凝胶助焊剂 | 高 |
| 准备工作 | **先用吸锡带清除所有出厂无铅焊锡** | 高 |
| 烙铁温度 | **约 380 °C**，细尖烙铁头 | 高 |
| 预热 | **不需要** | 高 |
| 热风 | 可选，批量操作更快，但必须使用尺寸合适的喷嘴 | 高 |
| 镊子 | 陶瓷反镊；可以夹取，但仍可能把 0.5 mm 元件弹飞 | 高 |
| 遮蔽 | 用 Kapton 胶带遮住周围区域 | 高 |
| 低熔点合金 | 可以使用 | 中等 |
| 练习 | 先在报废板上练习 | 高 |
| 每张卡耗时 | 有经验的改装者手工操作约 **20 分钟**，结果不必完美 | 中等 |

几个人最终采用的流程是：先用吸锡带把焊盘对上的出厂无铅焊锡清理干净，涂凝胶助焊剂，在一个焊盘上预上锡，用镊子放置元件并固定这一端，最后熔接另一端。用针头涂焊膏再配合热风枪，可以让元件自行对准；对于熟悉热风操作的人，这是更快的路线。

> [!CAUTION]
> **不要给整块板预热**
>
> 有人在频道中提议把整块板放进烤箱预热，但这一做法很快被否决为新手陷阱。已有记录的过度预热后果（红外炉加热风枪）包括**PCB 弯曲、内部走线断裂和 IC 被烤坏**，并会产生事后极难诊断的细微缺陷。这是这项返工最主要的新手失败模式。380 °C 的细尖烙铁配合不预热操作已经足够。

### 难度

这是常规的 0402 返工。24 颗电容需要焊到金手指旁边、带有标记且不拥挤的板背焊盘上。没有 BGA、没有植球、没有钢网、没有固件步骤，也没有需要编程的内容。有经验的改装者称这是“probably the easiest card to do PCIE mod”（大概是最容易做 PCIe 改装的卡），比需要完整 BGA 设备的 CMP 100HX 转 V100 “way easier”（容易得多）。手工操作每张卡约需 20 分钟。

> [!NOTE]
> **如果你是被请来报价的维修店**
>
> 整项工作就是：在客户交给你的、已经提供元件的卡上，把 24 × 0402 电容（220 nF、X7R、6.3 V 或更高）装到 PCIe 边缘连接器旁 `C1100`-`C1350` 组中的空焊盘上。先用吸锡带清掉焊盘上的出厂无铅焊锡，再使用含铅焊锡。
>
> 你不需要诊断，卡上也没有损坏，不需要执行固件或软件步骤。焊盘有标记、不拥挤，而且位于外表面。这项工作严格来说比维修店多年来一直在做的 CMP 100-210 转换更简单；后者需要移动跳线电阻*并*强制刷写，而这项工作只有电容，没有其他内容。
>
> 客户报告称，他们通常要被十多家店拒绝，才能找到一家愿意直接做这项工作的店。这才是流程的主要障碍，而不是返工本身。

另有一条频道内记录的提醒：流传的 `a100-unlock.pdf` / `cmp-170hx_a100_hardware-restore.pdf` 物料清单包含一颗 **Winbond 备份 VBIOS 芯片**以及其他与通道改装无关的部件。一位有经验的改装者读完该指南后，合理地认为它暗示需要钢网的完整 BGA 作业。事实并非如此。PDF 作者表示，要恢复 x16 只需要 PCIe 通道上的小元件；构建中的其他内容，都是试图在内部复刻 A100 的附加工作。

## 部分贴装与协商位宽

PCIe 位宽协商会回退到下一个合法位宽（16，然后 8、4、1），而不是直接彻底失败。因此，报告出的通道数可以直接用来诊断焊接质量。

| 正确贴装的电容 | 训练出的位宽 |
|---|---|
| 24 颗中 0 颗（出厂状态） | **x4** |
| 24 颗中 12 颗 | **x8** |
| 24 颗中 12 到 23 颗，或存在任何桥接/冷焊点 | **x8** |
| 24 颗中 24 颗 | **x16** |

电容改装后得到 x8，意味着**焊接不完整或存在桥接，并不是另一种硬件限制**。一位改装者在三张卡上的进展是：随着技术提高，从 x4 到 x8，再到 x16。另一张卡也在“after smaller readjustments”（经过几处小调整后）从 x4 变成 x8，最后变成 x16。第三位测试者停在 x8，并猜测链路需要活动负载才能扩宽；证据更充分的解释是冷焊点或边缘焊点。

补救方法是机械性的，而不是电气性的：在放大镜下回流并检查全部 24 个焊点，寻找立碑元件、两个焊盘之间的锡桥，以及只是搁在焊盘上却没有润湿焊盘的焊点。

这些情况都不会造成破坏。不完美的结果只会让链路以较低位宽训练，不会损坏显卡；你修复焊点期间，显卡仍会以它已协商出的位宽继续工作。没有尝试次数上限，也没有需要重置的状态。

## 验证

请使用 **`LnkSta`** 验证，绝不要只看 `LnkCap`。`LnkCap` 表示设备宣告的能力，在链路实际以更低速度或位宽训练时，仍可能显示 x16（或 Gen2）。这正是多数经不起检验的“it works”（能工作）说法的已知来源。

```bash
# 1. Find the card. Both SKUs enumerate as GA100 [CMP 170HX] (rev a1).
lspci -nn | grep -i nvidia
#   e.g. 0a:00.0 3D controller [0302]: NVIDIA Corporation GA100 [CMP 170HX] [10de:20c2] (rev a1)

# 2. The authoritative read: link status on the endpoint.
sudo lspci -s 0a:00.0 -vvv | grep -E 'LnkCap:|LnkSta:'

# 3. Kernel's own view, no root required.
cat /sys/bus/pci/devices/0000:0a:00.0/current_link_width   # want 16
cat /sys/bus/pci/devices/0000:0a:00.0/max_link_width       # 16
cat /sys/bus/pci/devices/0000:0a:00.0/current_link_speed   # 2.5 GT/s unless Gen2 is also applied

# 4. Driver's view.
nvidia-smi --query-gpu=pcie.link.gen.current,pcie.link.gen.max,pcie.link.width.current --format=csv
```

预期的变化如下：

| 状态 | `LnkSta` | `nvidia-smi` gen.cur、gen.max、width |
|---|---|---|
| 出厂状态：无改装、无解锁器 | `Speed 2.5GT/s, Width x4 (downgraded)` | `1, 1, 4` |
| 已做电容改装，未安装解锁器 | `Speed 2.5GT/s, Width x16` | `1, 1, 16` |
| 已安装解锁器，未做电容改装 | `Speed 5GT/s, Width x4 (downgraded)` | `2, 2, 4` |
| 电容改装 + 解锁器 | `Speed 5GT/s, Width x16` | `2, 2, 16` |

24 颗元件全部到位后，位宽字段中的 `(downgraded)` 后缀会消失，这是改装前后最清晰的单一信号。

> [!TIP]
> **速度字段中的 `(overdriven)` 属于正常现象**
>
> 根据 Gen2 的应用方式不同，`lspci` 可能打印 `LnkSta: Speed 5GT/s (overdriven), Width x16`。这个后缀只表示 `LnkSta` 报告的速度高于 `LnkCap` 宣告的速度；当链路速度被强制改变、但宣告能力没有被重写时，就会出现这种情况。它不是错误，也不代表链路不稳定。

完整验证流程请参见[验证](../procedures/verify.md)，失败分诊请参见[排障](../procedures/troubleshooting.md)。

> [!TIP]
> **在负载下测试**
>
> 没有流量时，许多平台会让链路降到较低状态。如果位宽或速度读数看起来不对，请在带宽测试期间重新读取，而不要只在空闲状态下读取。

## 改装能带来什么

| 配置 | 实测主机带宽 | 备注 |
|---|---|---|
| Gen1 x4（出厂状态） | **约 0.85 GB/s**（发送 0.80，接收 0.84） | OpenCL-Benchmark / clpeak |
| Gen1 x16（仅电容改装） | **2.88 GB/s**，读数平稳且无错误 | 理论标称值约为 4 GB/s；差距归因于 PCIe 1.1 信令开销 |
| Gen2 x4（仅软件） | **发送 1.68 GB/s / 接收 1.71 GB/s** | OpenCL-Benchmark、一张归档截图、未改装卡；设置脚本也独立预测“约 0.85 到约 1.7 GB/s，正好翻倍”。置信度中等 |
| 在协商为 x8 的电容改装卡上从 Gen1 到 Gen2 | **1.67 → 3.24 GB/s** | 一次 A/B 测试，单卡，Asus Prime Z370 / i3-8100 / 8 GB RAM。置信度中等。这**不是** Gen2 x4 的结果：由于显卡运行在 x8，3.24 GB/s 超过了 Gen2 x4 约 2.0 GB/s 的上限 |
| Gen2 x16（两者） | **6.63 到 6.67 GB/s** | `ocl_pcie_bw`；`nvtop` 在 `PCIe GEN 2@16x` 下显示 TX 7.061 GiB/s |
| Gen2 x16（两者），第二套平台 | **5.97 GB/s** 主机到设备，4 张卡读数完全相同 | 使用 `MAASJ105SB7224KFCA01` 的四卡构建、CUDA H2D、`MaxPayload` 256 字节。与 6.63 GB/s 的平台相比，这是主机侧差异；两者都处于 PCIe 2.0 x16 在 8 GB/s 上限下的正常范围。见[现场报告](#field-report-four-cards-at-gen2-x16) |

即使速度更容易通过软件获得，通道数仍然重要，因为平台的通道预算会独立限制可安装的显卡数量。纯软件的 Gen3 x4 解锁完全不需要焊接，这也是 Gen3 x4 成为社区下一个目标的原因。频道内有人把它描述为速度上等同于 Gen2 x16，但算术并不支持这一说法：Gen3 x4 约为 3.9 GB/s（8 GT/s、128b/130b、4 条通道），而 Gen2 x16 为 8 GB/s，因此它的性能位置更接近 Gen1 x16。无论如何，对于想在一台主机中塞入多张卡的人来说，“lanes are lanes”（通道就是通道）。参见[PCIe Gen3 和 Gen4](../frontier/pcie-gen3-gen4.md)。

链路位宽对推理吞吐量能做什么、不能做什么，请参见[LLM 推理](llm-inference.md)和[性能](performance.md)。流水线并行中的卡间流量可以忽略不计（一个隐藏维度为 5120 的模型每次跳转、每个 token 传输 10,240 字节，因此要达到约 25,000 tokens/s 才能占满一条 PCIe 1.0 通道），而张量并行和专家并行即使在 PCIe 2.0 x16 下也被判断为不可行。

### 软件代码树中没有任何相关内容

电容改装对解锁器不可见，而且这不是猜测，而是已经验证过的否定结论。发布版 `master` 以及 12 个未发布分支中的任何文件，都不含字符串 “capacitor”、“AC coupling” 或 “solder”，也没有任何通道位宽寄存器。对完整 git 历史执行 grep 也没有结果。发布版 `0007-pcie-gen2.patch` 只操作链路**速度**寄存器。

> [!NOTE]
> **来源更正**
>
> 一个广泛流传的说法称，分发版解锁 README 将这一限制记录为：“PCIe width is x4 (not x16): This is a hardware limitation of the CMP 170HX -- missing AC coupling capacitors on lanes 4-15.”（PCIe 位宽是 x4 而不是 x16：这是 CMP 170HX 的硬件限制，即通道 4 到 15 缺少交流耦合电容。）**发布版 `README.md` 中没有这段文字**，任何分支或 git 历史中的任何时点也没有。技术结论本身真实且证据充分，错误的只是把它归因于发布版 README。它最可能来自第三方指南。

## 现场报告：四张卡达到 Gen2 x16

一位社区成员分别为四张 CMP 170HX 卡装上 24 颗 Taiyo Yuden `MAASJ105SB7224KFCA01`（220 nF、6.3 V、X7R、0402），并提供了照片和日志。四张卡全部训练为 **PCIe 2.0 x16**，并连续运行四卡 LLM 推理，**没有出现任何 PCIe 错误**。这是继 2026-07-26 那次单卡观察之后，第二套达到 Gen2 x16 的独立平台，也是第一套包含多张卡、多个板卡修订，或任何错误遥测数据的平台。

> [!TIP]
> **只贴装了电容**
>
> 没有刷写 VBIOS：四张卡仍然都报告出厂版本 `92.00.6D.00.0A`。没有贴装 VRM 相位，没有移动跳线电阻，没有增加备份闪存芯片，板上也没有碰过其他焊盘。流传的 `a100-unlock.pdf` 物料清单列有一颗 Winbond 闪存芯片和其他一些部件；**x16 不需要其中任何一个**。这直接印证了 PDF 作者后来自己作出的说明：决定链路位宽的只有 PCIe 通道上的元件。

### 板卡

两种不同的丝印修订都完成了改装，结果相同：`180-11001-DAAA-B15` 和 `180-11001-DAAA-B35`，且都带有板卡料号 `699-11001-0108-600 G`。**此前从未记录过 B35 修订。** 四张卡都是运行 64 GB 显存解锁的 8 GB SKU，因此报告为 65536 MiB。

### 链路状态

四张卡使用同一主机，均完成电容改装，并加载了打过补丁的驱动，注册表参数为 `NVreg_RegistryDwords="RmForceEnableGen2=1;RMPcieLinkSpeed=0x2"`：

```text
LnkCap:  Port #0, Speed 2.5GT/s, Width x16, ASPM not supported
LnkSta:  Speed 5GT/s (overdriven), Width x16
LnkCap2: Supported Link Speeds: 2.5GT/s, Crosslink- Retimer- 2Retimers- DRS-
         MaxPayload 256 bytes, MaxReadReq 512 bytes
```

```text
0000:03:00.0: width=16 speed=5.0 GT/s PCIe maxwidth=16
0000:04:00.0: width=16 speed=5.0 GT/s PCIe maxwidth=16
0000:88:00.0: width=16 speed=5.0 GT/s PCIe maxwidth=16
0000:89:00.0: width=16 speed=5.0 GT/s PCIe maxwidth=16
```

请注意，在这套平台上，注册表 dword 路线只改变了 **`LnkSta`**；`LnkCap` 仍然宣告 2.5 GT/s，因此 `lspci` 打印的是 `(overdriven)`，而不是普通的 `5GT/s`。更早一份使用分支时代 Gen2 代码的报告则显示 `LnkCap: Speed 5GT/s`。这两种显示都代表正常工作的 Gen2 链路。重要的是 `LnkSta`，尤其是 `Width x16` 后面不能带 `(downgraded)` 后缀。

### 带宽

| 测量项目 | 结果 |
|---|---|
| 主机到设备、CUDA、每张卡 | **5.97 GB/s**，四张卡完全一致 |
| `MaxPayload` | 256 字节（在这台主机上实测最优；128 字节会损失吞吐量） |
| `MaxReadReq` | 512 字节 |

PCIe 2.0 x16 在 8b/10b 编码后的上限为 8 GB/s。以此为参照，5.97 GB/s 约为 75%，计入 TLP 和 DLLP 开销后属于正常范围。这个结果低于第一套 Gen2 x16 平台记录的 6.63 到 6.67 GB/s；差异来自主机侧（根复合体和芯片组不同），不是改装本身的属性。对比 4 GB/s 上限下 Gen1 x16 的 2.88 GB/s，也能看到相同的 75% 比值。

## 拆解

在安装水冷头、接触 SPI 闪存芯片，以及（对于已组装的卡）进行任何板级返工之前，都需要先完成拆解。所需紧固件工具为 **Torx T10 和 T15**。

1. 拆下 4 颗 PCIe 安装支架螺丝，并**保存支架**：安装水冷头时要把它重新用作垫片。另一侧的支架不需要拆下。
2. 将卡翻到背面，拆下背面的 10 颗螺丝。
3. 再次翻转并打开前盖；PCIe 支架会脱落，散热器随之露出。
4. 拧下固定右上方电源线缆和连接器的支架。
5. 用塑料撬棒把硬质电源线缆从背板上撬开。线缆松开之前，PCB 无法移动。
6. **最难的一步。** PCB 不能直接垂直抬起，因为 PCIe 连接器滑入了背板中的槽。先让 PCB 沿水平方向远离连接器，直到它横向错开几毫米，然后在继续水平移动的同时向上抬起。已有记录显示，这一步曾让一个知名硬件频道第一次尝试就失败。
7. 拆下 PCB 背面的 4 颗弹簧螺丝，并**保存 4 个垫圈**。它们不能与售后水冷头附带的塑料垫圈互换。
8. 从没有元件的一侧用塑料撬棒撬下散热器，同时托住散热器，防止它掉到 PCB 上。

便于规划的物理尺寸：PCB 长 27 cm；算上 I/O 挡板和已插入的 EPS 连接器后总长 29 cm；散热器螺栓孔距为 57 × 68 mm（垂直方向 68 mm，水平方向 57 mm）；晶片封装约为 55 × 55 mm。

## 散热改装

运行层面的细节见[散热](cooling.md)；本节只介绍物理操作。

### 水冷头

**Bykski `N-TESLA-A100-X-V2`** 适用于 A100 40 GB、CMP 170HX 和 A30 24 GB 板卡，使用标准 G1/4 接头。它**必须是 V2（全金属）修订版**；更早的非 V2 版本使用透明亚克力。不要把它与不兼容的 A100 **80 GB** 水冷头混淆。唯一一份已记录安装报告中的实用提醒是：水冷头发货时没有用户手册，只有一份两句话的在线快速入门；随附的内六角扳手尺寸也不对，因此应准备一套公制内六角扳手。A100-PCB 水冷头可以安装，并会露出 NVLink 金手指。

> [!CAUTION]
> **放下水冷头前，盖住每一个未贴装的 IC 焊盘**
>
> 安装水冷头时最具破坏性的错误，就是让未贴装 IC 的焊盘裸露。水冷头上的金属接触柱可能跨过裸露的铜焊盘并造成短路，**永久损坏显卡**。由于 170HX 是一块元件被删减的 A100 板，它比真正的 A100 多得多裸露焊盘，因此安装水冷头的风险也相应更高。
>
> 用绝缘材料盖住所有处于接触柱覆盖范围内的焊盘：ASIC 左右两侧的 DrMOS MOSFET；ASIC 左下和右下方的焊盘；晶片右侧、位于一颗电感和一颗电容之间的 PMIC；以及晶片左侧、3.3 µH 电感下方的两颗 PMIC。导热膏（豌豆大小）只能涂在 GPU/HBM 铜均热板上。
>
> 置信度说明：这条指示来自已有记录的操作流程，其作用机制也合理，但因果归因只建立在一张安装约一小时后损坏的卡上。作者的首要怀疑还与一个预先存在的挖矿磨损故障和一个漏装支架的理论相竞争，始终没有被决定性地单独验证。无论如何，都要把焊盘盖好。

装配细节：

- 重用拆解第 7 步保存的**原装 4 个垫圈**，不要使用水冷头附带的塑料垫圈；但螺丝应使用**水冷头配套的弹簧螺丝**，而不是原装螺丝。
- 先装入一颗弹簧螺丝，然后把电源连接器插入水冷头的槽中。必须先拧下两颗六角螺母（件 5），才能拆下连接器固定盖（件 4）。随后装上剩余的 3 个垫圈和螺丝。
- **在 PCB 与背板之间的左侧，重新装回原装 PCIe 插槽支架**，把它用作垫片。它增加的高度决定了背板与 PCB 之间的间距。
- 背板用 4 颗 **9.5 mm M2** 螺丝固定，先装两颗，再装另外两颗。
- 加入冷却液之前，先完成一次 **15 分钟加压泄漏测试**。

原装散热器上的热界面材料：主要区域使用 1.5 mm 软垫，电感上使用 3 mm 软垫，晶片上另有液态导热膏或液态导热垫。有人提出主要区域应使用“2 mm”软垫，但说法前带有 “I think”，因此置信度更低；T10/T15 批头则得到两份报告的相互佐证。

### 风冷

57 × 68 mm 的螺栓孔距与 RTX 4080 散热器或 socket-478/370 安装孔距足够接近，因此可以进行改装；有报告称一款 4080 散热器“kinda”（勉强）能够安装。流传着两种打印方案：

- 常见的 3D 打印导流罩（`CMP_170HX_Fan_Shroud_Fixed.stl`、`CMP_170HX_Dual_Shroud_Fixed.stl`）采用摩擦配合，时间久了会脱落，而且壁厚很薄，即使使用 PETG 也不够坚固。现有的只有 STL 文件，因此若想方便地修改，就需要 STEP 文件。
- Level1Techs A 系列鼓风机转接座（`l1 a100 blower.stl`，52.3 KB，发布于 2023-07-05）是无需支撑的打印件，通过螺丝固定到卡远端已有的螺丝孔上；电源连接器旁边设有倾斜的低矮段，方便手指伸入。线程中有人询问过耗材材料、打印设置、气流方向和耐用性后续情况，但始终没有得到回答。

> [!WARNING]
> **无论安装什么散热器，都必须同时为 VRM 散热**
>
> 只覆盖晶片的散热器会让功率级没有任何冷却。一份有争议的现场报告称，某些卡在长期挖矿后反复烧毁板背元件；报告怀疑操作者只监控核心传感器（约 56 °C），却在受带宽限制的工作负载下让 VRM 过热。一位长期使用这张卡的有经验用户完全否认这种故障模式。问题尚未解决，但无论原因是什么，这条设计原则都成立。

> [!NOTE]
> **未解问题**
>
> V100 均热板水冷头是否适用于 170HX？有人提出过这个问题，但从未实际测量。购买前，应将 57 × 68 mm 的螺栓孔距和 55 × 55 mm 的晶片尺寸与水冷头规格书对照公布的数据进行核对。一个相关的可靠数据是：SXM3 散热器经过小幅修改后可以与 SXM2 互换。注意：170HX 卡体较厚，通用 NVIDIA 鼓风机风道可能无法安装。

## 电源连接器与电源改装

这张卡使用单个 **EPS 8-pin**，不是 PCIe 8-pin。大多数 PSU 集成的 EPS 线缆带有尺寸过大的卡扣，物理上无法插入，因此通常的解决方案是使用 **2× PCIe-8-pin-to-EPS 转接座**。一条模组化 EPS12V 线缆的**两端**都必须是 4× 12 V 和 4× GND，而一个质量良好的引脚只能承载约 70 到 80 W。DevCap 报告的插槽功耗上限是 75 W；TDP 为 250 W，300 W 并不是软件上限：在出厂固件上，最大值等于默认值，因此 `nvidia-smi -pl` 只能把显卡功耗在 100 W 到 250 W 之间调低。只有 NVIDIA 发布的 300 W “OC mining” VBIOS 会提高上限，而且只对实际装有该 VBIOS 的卡有效。参见[供电与 PSU](power-and-psu.md)。

### 分流电阻改装

> [!CAUTION]
> **从未执行，从未测量**
>
> 恢复完整的 A100 TDP *预计*只需要简单的分流电阻改装，而不是修改固件。**现有资料中没有任何人实际执行或测量过这种改装。** 这是有经验的硬件改装者作出的专家判断，对这一等级的显卡来说看起来合理，但分流电阻的位置、电阻值、最终功耗以及热后果全部未知。有人提出通过软件或 VBIOS 把上限调到 400 到 500 W，作为不愿进行分流改装者的替代方案，但这一方案同样从未实现。在这张卡上尝试分流改装，属于没有现成路线、却显然可能直接毁卡的未知领域。

### 未贴装的 4-pin 焊盘

PCB 上有一个未贴装的 4-pin 焊盘，经测量带有 12 V，因此被怀疑是风扇接口。

> [!NOTE]
> **未解问题**
>
> 没有人确认过配套插座的料号、是否存在转速计线，或它是否支持 PWM 控制。之所以希望确认它，是因为它可以在不使用外部控制器的情况下实现每张卡独立的风扇控制。下一步应是在空闲和负载状态下对剩余两根引脚进行示波器测量，并在泄露的原理图中追踪它们。

## 跳线电阻

板卡在靠近去耦电容的左上区域有 5 对跳线电阻：5 个跳线共 10 个焊盘，元件没有标记，通常是 100 kΩ 0402 电阻，并被上拉到 0 V 或 1.8 V。每个跳线由一颗电阻和一个空焊盘组成，因此把元件在两个位置之间移动，就会翻转该跳线位。在 PCB 上从左到右依次为：

| 跳线 | 设计编号 | 功能 |
|---|---|---|
| Strap1 | R986, R987 | RAMCFG[1] |
| Strap0 | R989, R990 | RAMCFG[0] |
| Strap3 | R993, R994 | VGA_DEVICE |
| Strap4 | R999, R1000 | PCIE_CFG |
| Strap2 | R1004, R1005 | RAMCFG[2] |

R1004 和 R1005 是**同一个**跳线位置的两个替代焊盘，不是两颗独立电阻。同一来源还提到第六个跳线，即 **R240/R241 处的 DEVID_SEL**，但它从未在实物板上被定位。

出厂模式为：A100 40 GB 和 170HX 10 GB 都是 `LLLLH`；170HX 8 GB 是 `HHLLH`。

> [!CAUTION]
> **一种跳线模式会让主机无法启动**
>
> 在 10 GB 卡上设置 `LLHHH` 会导致**完全无法 POST**。把 A100 的完整跳线配置复制到 170HX 上，结果是**开机时检测不到显卡**。跳线实验原则上可以恢复，但在把元件移回去之前，错误的模式可能让一个原本正常工作的系统无法使用。

> [!NOTE]
> **未解问题**
>
> Strap3（VGA_DEVICE、R993/R994）和 Strap4（PCIE_CFG、R999/R1000）究竟有什么作用？这个问题于 2026-07-26 提出，但从未得到回答。有一条意外的数据：一位测试者原本想移动 R1004，实际却移动了 Strap4，将 `LLLLH` 变成 `LLLHH`，并报告显存没有受到影响。PCIe 能力协商是否发生变化，从未被测量。下一步是有意重复该实验，并在前后分别捕获 `lspci -vv` 的 LnkCap/LnkSta。

> [!NOTE]
> **未解问题**
>
> 在实物板上找到 R240/R241（DEVID_SEL）的位置。设备 ID 是发布版驱动据以选择几何布局的依据，而 `OPT_DEVID_SW_OVERRIDE_DIS @ 0x00820584 = 0x00000001` 关闭了所有通过软件修改它的路径。一个合理但尚未大规模尝试的搜索方法是：在 PCB 上带有小于 500 的设计编号的一面、200 系列设计编号区域内，寻找一颗紧挨空焊盘的电阻。有人询问商业 AI 助手，得到了一份自信却完全虚构的板级拓扑；这件事被记录为一个警示性数据点。

## VBIOS 刷写硬件

这块板**没有 OS 级别的刷写路径**。写入 VBIOS 意味着直接把芯片夹夹在 SOIC 元件上，这需要拆下散热器；但使用芯片夹写入时，不需要修改板上的无源器件。

> [!CAUTION]
> **上电前启用写保护**
>
> 刷写失败 `0xBADF3000`、以及板卡无法读取闪存，原因是**重新上电前没有对 SPI 芯片启用写保护**。恢复方法是用芯片夹直接重刷 SOIC，然后设置写保护。相关症状是 RM init 适配器失败。置信度：中等（建议来自一位曾在这些板上做过 SOIC 和 VRM 工作的人；报告问题的用户随后不久恢复了显卡）。参见[恢复](../procedures/recovery.md)和[VBIOS](../hardware/vbios.md)。

流传的硬件恢复物料清单中的 Winbond BIOS 芯片，是用来从错误刷写中恢复的**备份 VBIOS 芯片**。它不是 PCIe 或显存解锁的一部分。

## 无论焊接多少都无法修复的部分

这些边界已经烧录在熔丝中，或固化在封装内部，限制了本页讨论的每一种硬件方案。详情见[熔丝与 OTP](../hardware/fuses-and-otp.md)。

| 限制 | 机制 | 为什么焊接没有帮助 |
|---|---|---|
| SM 数量为 70（5 个 GPC、35 个 TPC、CC 8.0） | `OPT_GPC_DISABLE 0x00820350` OTP | 每个 GPC 对应的 `CTRL_OPT`（`0x00820838 + i*4`）和 `RECONF_OVR`（`0x00820a40 + i*4`）读数都已经是 `0x00000000`；枚举出的数量恰好等于熔丝下限，没有被额外压制的单元 |
| 显存容量上限 | `FUSE_FBP_DISABLE 0x00820364`、`FUSE_FBPA_DISABLE 0x00820368`、`FUSE_FBIO_DISABLE 0x0082036c`、`ROP_L2_DISABLE 0x008202c4` | 对应的 DEFECTIVE 寄存器读数全部为 `0x0`，说明不存在真实的晶片缺陷，只有启用中的禁用掩码；向 DISABLE 寄存器写入 0 不会改变这些掩码 |
| 损坏的 HBM 堆叠 | 邦定在**硅中介层**上，而不是 PCB 上 | 回流焊无法解决。一位成员曾用热风枪在几张 HBM2 GPU 上以多种温度尝试数小时，没有成功。HBM 堆叠还含有内部熔丝，因此堆叠内有缺陷的晶片可能已被永久熔除 |
| NVLink | `FUSE_NVLINK_DIS` 加上未贴装的接口 IC | 边缘金手指在物理上存在，A100 水冷头也会露出它们，但要启用 NVLink，既需要缺失的 IC，*也需要*一根处于设定状态的熔丝。合理推测中介层本身还带有 eFuse。参见[NVLink](../frontier/nvlink.md) |
| ECC | 已由熔丝关闭，没有可用开关，也没有遥测 | 参见[ECC](../frontier/ecc.md) |
| 显示输出 | 板上没有显示硬件 | 部分 CMP 板上确实存在显示焊盘，但还需要“a ton of missing SMD components”（大量缺失的 SMD 元件）；在 170HX 上，显示功能被记录为永久缺失 |
| 设备 ID | `OPT_DEVID_SW_OVERRIDE_DIS 0x00820584 = 0x00000001`；DEVIDA/DEVIDB 已在晶片内部熔断，并由选择跳线锁存 | 软件无法覆盖它，而负责选择的跳线从未被定位 |

更准确的总体结论，可以纠正早期那种笼统的“hardware unlock is impossible”（硬件解锁不可能）的判断：**硬件改装无法改变熔丝设定的边界，但可以恢复 PCB 上因删减元件而缺失的功能。** 电容改装正是这种区别能够产生实际效果的例子。

## 相关卡

**CMP 100-210**（V100 级部件）转为 V100 或 Titan V，需要按顺序完成**两项操作**：移动跳线电阻，然后强制刷写。在跳线阵列上，把现有电阻从底部焊盘移到顶部焊盘，使配置变为 `HHLLHH`（出厂状态据报告为 `HLLLHH` 或 `HLLHHH`），然后使用 `omgvflash` 强制刷写官方 Tesla V100 16 GB VBIOS。不需要不同阻值，只需要移动位置。只刷写已经经过测试，结果**会失败**：显卡能够枚举，但设备 ID 不变，因此 Linux 驱动会把它识别为 CMP 100 并加载错误的二进制 blob。完整流程的置信度为中等（有一人提供照片并成功完成多张卡，但日志中没有第二方完成该流程）；“只刷写是不够的”这一结论的置信度为高，因为它经过了直接测试。

> [!WARNING]
> **电容改装的结果不能套用到 CMP 100-210**
>
> 170HX 的通道数纯粹是电容问题（仅焊接、不做任何软件操作就能得到 x16，且已由多方确认）。一份关于 CMP 100-210 的相反报告称，在那张卡的 PCIe 插槽附近加电容**不能**解锁 x16，而且该卡的通道数同样受软件控制。两者使用的是不同晶片，因此没有理由认为答案必须相同；但关于 170HX 的说法在传播时经常省略了这个限定。

## 也可以购买改装好的卡

截至 2026 年 7 月下旬，一家大型深圳供应商在闲鱼上以 **1000 元（约 $140）** 的价格提供电容改装服务。已改装卡的挂牌价为 8800-9800 元，未改装卡为 7000-7500 元；在 Alibaba 上，价格约为 $1500，对比未改装卡的约 $1150-1300，溢价约 $300。一位卖家确认，溢价的原因是 x16。

> [!WARNING]
> **买家注意：约 $1500 可能对应两种不同的东西**
>
> 另一家*不同供应商*提供的约 $1500 档位是**翻新，不是电容改装**。务必问清楚卖给你的究竟是哪一个档位。一些闲鱼挂牌还会为捆绑的“cracked system disk”（破解系统盘）额外收费，它其实是预先制作好的解锁启动映像。

### 如果能找到愿意接单的本地店，价格更低

深圳的服务价并不是最低价。一位构建者把自己的卡交给本地电子维修店处理，**每张卡约 $50**，约为 1000 元服务费的三分之一，不需要支付运费，显卡也不用离开所在国家。

难点不在焊接，而在找到愿意接这项工作的店。那位构建者在找到一家愿意只安装元件、不争论改装原理的店之前，曾被**十多家店**拒绝。应当预期会遭到拒绝：维修店通常希望先诊断显卡，质疑缺失电容是否真的是故障原因，或者拒绝维修不是由自己售出的硬件。按照板级维修标准，这项工作本身并不特别，这正是拒单率令人意外的原因。

以下建议来自这段经历，而不是任何测量结果：

- 按工作内容提出要求，不要先解释原理。“Populate 24 0402 capacitors on these marked pads, parts supplied”（在这些标记焊盘上装 24 颗 0402 电容，元件由客户提供）是一项可以直接报价的工作。解释这是给矿卡解锁 PCIe 通道，反而会引发“到底是否有效”的争论，而拒单往往就从这里开始。
- 自己提供电容。整套元件只需几美元，同时可以消除维修店对采购渠道的顾虑。见[物料清单](#bill-of-materials)。
- 板级微焊接店和手机维修店比普通 PC 维修店更适合。它们通常已经有热风枪、显微镜和助焊剂，0402 焊接对它们来说属于常规工作。
- 接受维修店不会为结果提供质保。它无法保证，因为链路能否训练为 x16 取决于显卡本身，不仅取决于焊点。

按每张卡 $50 计算，这个价格低于 1000 元服务费，也低于预改装卡收取的约 $300 溢价。
